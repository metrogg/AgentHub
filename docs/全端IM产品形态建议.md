# AgentHub 全端 IM 产品形态建议

AgentHub 应该更像微信/飞书，而不是传统控制台。核心不是“功能页面集合”，而是“会话驱动的 Agent 协作客户端”：用户打开任意端，第一眼看到的都应该是消息、联系人、工作台和我的设备。

## 产品定位

推荐定位：

> AgentHub 是一个以 IM 为 Shell 的多 Agent 协作客户端。每个 Agent 是联系人，每个 Workspace 是群聊，每个任务和产物都是消息卡片。

这意味着所有端都应该围绕同一套心智组织：

- 消息：最近会话、单聊、群聊、任务进度、审批提醒。
- 联系人：Agent、工具、团队成员、设备。
- 工作台：Workspace、产物、代码任务、部署、知识库。
- 我的：连接状态、模型设置、权限、安全、设备同步。

## 全端信息架构

### 移动端

移动端最像微信：

- 默认首页是“消息列表”，不是欢迎页。
- 底部四个 Tab：消息、Agent、工作台、我的。
- 聊天页只保留轻量能力：发消息、@Agent、查看流式输出、审批、预览产物。
- 不在手机端做复杂配置和代码操作。
- 通过扫码连接电脑端，手机作为“随身遥控器”。

### Web 端

Web 端更像飞书工作台：

- 左侧会话列表是主入口。
- 中间是聊天线程。
- 右侧是上下文面板：Agent 成员、任务、产物、审批、预览。
- 设置、Agent 配置、Skills 市场都应该从“工作台”进入，而不是割裂成独立后台。

### 桌面端

桌面端是完整生产力客户端：

- 保留 Web 端三栏结构。
- 增强本地能力：打开项目文件夹、CLI Agent、文件预览、通知、快捷键。
- 支持多窗口，但每个窗口仍然围绕一个 IM 会话或工作台视图。

## 关键改造建议

1. 取消“工具后台感”

   减少设置型入口的视觉权重，把核心入口集中到消息列表、Agent 联系人和工作台。

2. 会话列表成为所有端第一屏

   首屏应该展示最近会话、置顶会话、未读/运行中任务，而不是空白欢迎页。

3. Agent 联系人化

   Agent 要像联系人一样可搜索、可置顶、可查看资料页。资料页包括角色、能力、运行时、权限、最近合作会话。

4. Workspace 群聊化

   Workspace 不应该只是项目容器，而是一个群聊。Architect、Coder、Reviewer、Orchestrator 都是群成员。

5. 产物消息卡片化

   Diff、预览、部署、文档、图片都应该作为消息卡片出现，用户可以在卡片上确认、驳回、打开、分享。

6. 审批移动端优先

   手机端最适合做审批：允许执行、合并 Diff、继续任务、停止任务、查看风险摘要。

7. 多端同步统一

   Web/桌面/移动端共享同一套会话、消息、流式事件和设备配对状态。移动端不直接运行 Agent，只发送命令并接收结果。

## 推荐落地顺序

1. 移动端改为微信式消息首页。
2. 增加底部 Tab：消息、Agent、工作台、我的。
3. Web/桌面左侧栏改为“消息”主导航，Agent/Workspace 作为 IM 对象聚合。
4. Workspace 详情页改为群资料页。
5. 产物和审批统一变成消息卡片。
6. 手机端补审批卡片和产物预览。

## 设计原则

- 消息优先，配置后置。
- 会话即上下文。
- Agent 即联系人。
- Workspace 即群聊。
- 产物即消息。
- 手机负责轻操作，桌面负责重执行。
