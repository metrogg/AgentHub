## 1. WebSocket 实时协议

### 1.1 连接端点

```
ws(s)://<host>/ws
```

### 1.2 事件类型枚举

```ts
enum WsEvent {
  // 消息生命周期
  MessageNew        = 'message:new'
  MessageStream     = 'message:stream'
  MessageCompleted  = 'message:completed'
  MessageMetadata   = 'message:metadata'
  MessageCancelled  = 'message:cancelled'

  // AG-UI 协议事件
  AgUiEvent         = 'ag-ui:event'

  // Agent 状态
  AgentTyping       = 'agent:typing'

  // 制品通知
  PreviewReady      = 'preview:ready'
  DiffReady         = 'diff:ready'

  // 会话管理
  SessionJoin       = 'session:join'
  SessionJoined     = 'session:joined'

  // 兼容旧任务看板事件（仅历史输入，不再作为主输出）
  TaskBoardPlanReady           = 'task_board:plan_ready'
  TaskBoardTaskProgress        = 'task_board:task_progress'
  TaskBoardRunCompleted        = 'task_board:run_completed'
  TaskBoardClarificationNeeded = 'task_board:clarification_needed'
}
```

### 1.3 消息帧格式

```json
{
  "type": "message:stream",
  "payload": { "sessionId": "...", "content": "...", "messageId": "..." }
}
```

### 1.4 客户端连接生命周期

```
connect()
  ├─ 创建 WebSocket → ws(s)://<host>/ws
  ├─ onopen → 重新 join 所有已跟踪的 session
  ├─ onmessage → 分发给注册的 listener
  ├─ onclose → 2 秒后自动重连
  └─ onerror → 关闭 socket

joinSession(sessionId)
  ├─ socket 已连接 → 发送 { type: 'session:join', payload: { sessionId } }
  └─ socket 未连接 → 触发 connect()

joinSessions(sessionIds[])
  └─ 逐个调用 joinSession

disconnect()
  └─ 清除重连定时器 → 关闭 socket → 清空 session 集合
```

### 1.5 服务端房间模型

```ts
// sessionRooms: Map<string, Set<ServerWebSocket>>
// 跟踪每个 session 有哪些 WebSocket 连接

joinRoom(sessionId, ws)     // 将 ws 加入 session 的房间
leaveRoom(sessionId, ws)    // 将 ws 从 session 房间移除
cleanupWebSocket(ws)        // ws 断开时清理所有房间引用

broadcastSessionEvent(sessionId, data)
  // 序列化 data 为 JSON
  // 遍历 session 房间内所有 ws
  // readyState === 1 (OPEN) 时发送
```

## 2. A2A 通信协议

### 2.1 协议版本

A2A v0.3.0，使用 `@a2a-js/sdk` 定义的 `MessageSendParams`、`Message`、`Task` 等类型。

### 2.2 扩展 URI

```
https://agenthub.dev/extensions/a2a/internal/v1
```

### 2.3 任务分派信封

```ts
interface AgentHubA2AEnvelope {
  protocolVersion: '0.3.0'
  method: 'message/send'
  params: MessageSendParams        // A2A SDK 标准参数
  contextId: string                // = groupSessionId
  taskId: string                   // workspace_tasks.id
  runId: string                    // orchestrator_runs.id
  workspaceId: string
  groupSessionId: string           // 群聊会话 ID
  childSessionId: string           // 子会话 ID
  fromAgentId: string              // Orchestrator Agent ID
  fromAgentName: string
  toAgentId: string                // 目标 Agent ID
  toAgentName: string
  referenceTaskIds: string[]       // 依赖任务 ID 列表
}
```

### 2.4 分派流程

```
buildA2ADispatchEnvelope(params)
  ├─ 解析 Orchestrator Agent（roleType === 'orchestrator' 或名称含 'orchestrator'）
  ├─ 创建 A2A Message:
  │   role: 'user'
  │   parts: [{ kind: 'text', text: promptContent }]
  │   extensions: [A2A_INTERNAL_EXTENSION_URI]
  │   metadata: { runId, workspaceId, groupSessionId, childSessionId, agentIds, taskTitle, taskType }
  └─ configuration: { acceptedOutputModes, blocking: true, historyLength: 20 }
```

### 2.5 响应 Task 构建

```ts
// buildA2AExecutionTask(params) 返回:
{
  kind: 'task',
  id: taskId,
  contextId: groupSessionId,
  status: { state: toA2ATaskState(taskStatus), timestamp },
  artifacts: [buildA2AArtifact(artifact), ...],
  history: [originalRequestMessage, agentResponseMessage],
  metadata: { runId, workspaceId, groupSessionId, childSessionId, fromAgentId, toAgentId, referenceTaskIds }
}
```

### 2.6 状态映射

| AgentHub TaskStatus | A2A TaskState |
|---|---|
| `pending` | `submitted` |
| `running` | `working` |
| `done` | `completed` |
| `cancelled` | `canceled` |
| `blocked` | `input-required` |
| `failed` | `failed` |
| `skipped` | `rejected` |

### 2.7 消息格式

```ts

{
  kind: 'message',
  messageId: uuid,
  contextId: groupSessionId,
  taskId: taskId,
  role: 'agent' | 'user',
```

## 6. 计划生成与协作模式

### 6.1 Planner 计划生成流程

```
Planner.createPlan(input: PlannerInput)
  ├─ 1. 接收用户目标、当前可用 Agent、关系和工作区上下文
  ├─ 2. Orchestrator/Planner 模型生成计划
  │     generateWithLlm(goal, agents, relations) → plan JSON
  ├─ 3. 规范化和校验
        normalizePlannerOutput(plan) → ExecutionPlan
```

说明：旧版曾包含 `findBestSpec(goal)`、Spec-first 架构规格生成和阶段骨架注入。该路径已经从运行链路移除，因为它会把固定模板/正则判断包装成 Orchestrator 分工。后续如恢复 Spec，只能作为用户显式提供的契约约束，不作为内置场景模板。

### 6.2 协作模式

```ts
type CollaborationMode = 'pipeline' | 'mapreduce' | 'supervisor'
```

| 模式 | 并发数 | 说明 |
|---|---|---|
| `pipeline` | 1 | 串行执行，任务严格按序 |
| `mapreduce` | 3 | 并行执行，最多 3 个任务同时运行 |
| `supervisor` | 3 | 并行执行 + 支持动态注入新任务 |

### 6.3 旧 ProjectSpec 状态

`ProjectSpec` 属于旧 Spec-first 规划尝试，已经从 Planner 运行链路移除。当前优先让 Planner 直接输出 `ExecutionPlan`，并通过 task output contract、blackboard schema、allowed paths 和 validation commands 约束结果。

## 7. TaskGraph 图算法

### 7.1 数据结构

```ts
class TaskGraph {
  private tasks: ExecutionTask[]
  private statuses: Map<string, TaskStatus>  // taskId → status

  constructor(tasks: ExecutionTask[])        // 初始化所有任务为 Pending
}
```

### 7.2 核心方法

| 方法 | 算法 | 说明 |
|---|---|---|
| `getReadyTasks()` | 线性扫描 | 返回 Pending 且所有依赖为 Done 的任务 |
| `getRunningTasks()` | 线性扫描 | 返回 Running 状态的任务 |
| `getFailedTasks()` | 线性扫描 | 返回 Failed 状态的任务 |
| `getBlockedTasks()` | 线性扫描 | 返回 Blocked 状态的任务 |
| `allDone()` | 线性扫描 | 所有任务为终态（Done/Failed/Cancelled/Blocked/Skipped） |
| `allSucceeded()` | 线性扫描 | 所有任务为 Done |
| `detectCycles()` | DFS | visited + recursionStack 集合，检测有向环 |
| `getExecutionOrder()` | Kahn 拓扑排序 | 入度 + 邻接表，返回有序任务 ID |
| `markBlockedByFailedDependencies()` | 迭代传播 | 依赖失败 → 当前 blocked，迭代至无新变化 |
| `addTasks(tasks)` | 追加 | supervisor 模式中途动态添加任务 |

### 7.3 TaskScheduler 执行循环

```
TaskScheduler
  ├─ 图: TaskGraph（内部持有）
  ├─ 并发: Semaphore(3)（pipeline 模式为 1）
  ├─ 轮询: 每 200ms 检查一次
  ├─ 流程:
  │   while (!graph.allDone()) {
  │     ready = graph.getReadyTasks()
  │     for (task of ready.slice(0, semaphore.available)) {
  │       semaphore.acquire()
  │       dispatch(task)   // 异步执行，完成后 release
  │     }
  │     await sleep(200)
  │   }
  └─ 取消: AbortController 传播到所有运行中任务
```

### 7.4 拓扑排序示例

```
任务依赖图:
  A → B → D
  A → C → D
  C → E

拓扑排序结果: [A, B, C, D, E] 或 [A, C, B, D, E]

就绪序列:
  第 1 轮: [A]          (无依赖)
  第 2 轮: [B, C]       (A 完成)
  第 3 轮: [D, E]       (B+C 完成，D 依赖 B+C，E 依赖 C)
```

```ts
  naming: Record<string, string>     // 命名规范
  forbidden: string[]                // 禁止操作
  imports?: { order: string[] }      // 导入顺序
  formatting?: Record<string, unknown> // 格式化规则
}
```

### 9.5 系统提示组装流程

```
buildSystemPrompt(ctx: HarnessContext)
  ├─ 1. 匹配最佳 Skill
  │     intersection(agent.capabilityTags, skill.applicableCapabilities || skill.applicableTags)
  ├─ 2. 收集适用 Rules（当前加载全部）
  ├─ 3. 构建基础提示:
  │     agent.systemPrompt + agent.role + agent.description
  ├─ 4. 有 Skill 匹配时:
  │     renderSkillTemplate(skill.systemPromptTemplate, {
  │       BASE_PROMPT, RULES, TASK_DESCRIPTION,
  │       WORKSPACE_PATH, AGENT_NAME, RULES.<id>
  │     })
  └─ 5. 无 Skill 时组装:
        runtimeType + capabilityTags + toolPermissions
        + sandboxPolicy + contextPolicy + workspacePath
        + 【规范约束】...【规范结束】 块
        + 审批警告（如需要）+ 结束指令
```

### 9.6 规范块格式

```
【规范约束】

### <规则名称>
- 约束 1
- 约束 2

禁止：
- 禁止操作 1

命名规范：
- key: value

【规范结束】
```

### 9.7 已移除的旧 Spec 触发匹配

旧实现曾按 `triggers` 正则匹配用户目标，并返回第一个命中的 Spec。该逻辑已经移除。当前系统不再通过静态 Spec 触发器判断用户意图、分配 Agent 或注入阶段骨架。

### 10.3 执行流程

```
streamCodeAgentReply(prompt, envelope)
  ├─ 1. 校验适配器可用性（isCommandInstalled）
  ├─ 2. 解析执行目录（AgentExecutionEnvelope → worktreePath）
  ├─ 3. 构建 Skill 上下文（globalSkillRegistry.buildSkillContextWithPreset）
  ├─ 4. 组装完整提示（buildCodeAgentPrompt）:
  │     Agent 身份 + 角色 + 系统提示 + 工作区路径
  │     + 沙箱策略 + 工具权限 + Skill 上下文
  │     + 最近 6 条群聊历史 + 当前用户请求
  ├─ 5. 解析模型目标（agent config + CODING_TOOLS_CONFIG）
  ├─ 6. 前置检查:
  │     executionEnabled && installed && configured && valid cwd
  ├─ 7. Bun.spawn() 启动子进程
```

## 12. 执行信封与沙箱

### 12.1 AgentExecutionEnvelope

```ts
interface AgentExecutionEnvelope {
  runId: string
  taskId: string
  agentId: string
  agentName: string
  projectPath: string | null       // 项目根路径
  worktreePath: string | null      // 工作树路径（沙箱目录）
  sandboxPolicy: 'read-only' | 'workspace-write' | 'danger-full-access'
  envAllowlist: string[]           // 允许传递的环境变量白名单
  modelTarget?: {
    apiKey?: string
    provider?: string
    modelId?: string
    openaiBaseUrl?: string
    anthropicBaseUrl?: string
  }
  a2a?: AgentHubA2AEnvelope        // 携带的 A2A 信封
  sandboxProvider?: 'local-workdir' | 'docker' | 'cloud'
  isolation?: 'workdir' | 'container' | 'cloud'
}
```

### 12.2 环境变量白名单

```
PATH, Path, PATHEXT, ComSpec, SystemRoot,
HOME, USERPROFILE, APPDATA, LOCALAPPDATA,
TMPDIR, TEMP, TMP,
ANTHROPIC_API_KEY, ANTHROPIC_BASE_URL, ANTHROPIC_MODEL,
OPENAI_API_KEY, OPENAI_BASE_URL, OPENAI_MODEL,
GEMINI_API_KEY, GEMINI_MODEL,
DEEPSEEK_API_KEY, AGENTHUB_MODEL_API_KEY,
CODEX_HOME, OPENCODE_CONFIG, NODE_ENV
```

### 12.3 校验规则

- `runId`、`taskId`、`agentId` 必填
- 若 `sandboxPolicy !== 'read-only'` 且 `projectPath` 非空，`worktreePath` 必须非空
- 禁止直接回退到 `projectPath`（防止越权写入）

### 12.4 Windows 特殊处理

- CLI 命令使用 `.cmd` shim 或 npm 全局 bin 路径
- OpenCode 使用 `node <binPath>` 直接调用，避免 cmd.exe 8192 字符限制
- Codex/Claude 提示内容使用 ASCII-safe JSON 编码，防止编码损坏
