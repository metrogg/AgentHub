### 🔴 P0 - 关键问题（必须立即修复）

#### 1. Git 工作区混乱

**现状**：
- 有 **2 个未 push 的 commit**（`e48823f`、`af42dcc`）
- 有 **大量 staged 但未 commit 的改动**（11 个文件，267 行新增）

**风险**：
- 如果此时切换分支或 pull 同事更新，可能丢失工作
- staged 的 task-contract 改动与已有的 `e48823f` commit 中的改动可能有重叠

**建议**：
1. 立即 commit 当前 staged 改动，或确认是否需要与已有 commit 合并
2. 推送到 dev/wzd

#### 2. `readEnv` 残留 - 环境变量解析不一致

**现状**：
```
apps/server/src/routes/coding-tools.ts:838   function readEnv(key: string) { ... }
apps/server/src/services/code-agent-adapter.ts:1208  function readEnv(key: string) { ... }
apps/server/src/services/llm-client.ts:98    function readEnv(name?: string): string | undefined { ... }
```

`coding-tools.ts` 和 `code-agent-adapter.ts` 各自定义了 `readEnv` 函数，直接读取 `.env` 文件的原始值，**绕过 `env.ts` 的 Zod 解析和默认值**。

**风险**：
- `.env` 文件中的字符串 `"false"` 可能被错误解析为 truthy
- 与 `env.ts` 中定义的逻辑（如 `envBoolean` 预处理）不一致
- 这是之前已经导致过 Bug 的模式（`AGENTHUB_ENABLE_CODE_AGENT_EXECUTION` 开关问题）

**建议**：
- 统一使用 `env.ts` 中解析后的值
- 移除 `coding-tools.ts` 和 `code-agent-adapter.ts` 中的本地 `readEnv` 函数
- `llm-client.ts` 中的 `readEnv` 用于读取 API Key，这是合理的（需要原始值），但应重命名避免混淆

#### 3. 数据库 schema 可能不一致

**现状**：
- `sessions` 表实际列：`id, title, type, owner_id, created_at, updated_at, workspace_id, workspace_agent_id`
- Schema 定义中有 `metadata` 字段（`text('metadata', { mode: 'json' })`）
- Migration `0009_sessions_metadata.sql` 已应用，但实际表中**没有看到 `metadata` 列**

**风险**：
- 如果代码尝试写入 `metadata`，可能抛出 SQLiteError
- 这曾经导致过测试失败（之前的 session 中就有这个问题）

**建议**：
- 运行 `bun run db:migrate` 确认所有 migration 已应用
- 如果表结构与 schema 不一致，手动修复或重新生成 migration

### 🟡 P2 - 中等问题（可以稍后处理）

#### 7. TaskScheduler 中潜在的竞态条件

**位置**：`task-scheduler.ts:41`
```typescript
this.runTask(task, graph, results, executor, runController.signal).catch((err) => {
  logger.error({ err, taskId: task.id }, 'Task execution error')
})
```

**风险**：
- `runTask` 的异常被 catch 后只记录日志，**没有把任务标记为 failed**
- 如果 `runTask` 在 `semaphore.acquire()` 中抛出异常（如超时），任务状态不会被更新
- 调用方 `executePlan` 中的 `while` 循环可能无限等待

**建议**：
- 在 catch 中调用 `graph.setStatus(task.id, 'failed')` 并设置结果

#### 8. WebSocket 清理逻辑有隐患

**位置**：`agent-runner.ts:50`
```typescript
export function cleanupWebSocket(ws: ServerWebSocket<unknown>) {
  for (const [sessionId, room] of sessionRooms) {
    if (room.has(ws)) {
      room.delete(ws)
      if (room.size === 0) sessionRooms.delete(sessionId)
    }
  }
}
```

**风险**：
- 如果同一个 ws 被多次加入不同 room，只清理第一个匹配到的
- 但通常一个 ws 只关联一个 session，所以风险较低

**建议**：
- 添加 `break` 或确保清理所有匹配项

#### 9. `console.log/error` 残留（服务端）

**位置**：
- `apps/server/src/app.ts:25` - `console.error(err)`
- `apps/server/src/routes/coding-tools.ts` - 多处 `console.log/error`

**风险**：
- 生产环境可能泄露敏感信息
- 与 logger 体系不一致

**建议**：
- 统一使用 `logger` 替代 `console`

#### 10. Synthesizer 中 `plan.agents` 可能为空

**位置**：`synthesizer.ts:21`
```typescript
const sections = results
  .filter((r) => r.status === 'done')
  .map((r) => ({
    agent: r.agentName,
    ...
  }))
```

如果所有任务都失败，`sections` 为空，会返回固定文案。这是预期行为，但文案可以更丰富。

## 四、数据流健康度

```
用户消息 → ChatPage → WebSocket → agent-runner.ts → RuntimeRegistry.resolve()
                                           ↓
                                    LLM / CodeAgent / NativeTool
                                           ↓
                                    输出写入 messages 表
                                           ↓
                                    WebSocket broadcast → 前端更新
```

**健康度**：🟢 良好

Orchestrator 数据流：
```
@orchestrator → messages.ts → createPlan() → 用户确认 → dispatch()
                                                        ↓
                                               OrchestratorEngine.startRun()
                                                        ↓
                                               Planner → TaskScheduler → executeTask()
                                                        ↓
                                               ConflictResolver → Synthesizer
                                                        ↓
                                               结果写入群聊 session
```

**健康度**：🟢 良好，但需注意：
- `executePlan` 中的 `while (!graph.allDone())` 循环在极端情况下可能不退出（如任务状态未正确更新）
- 建议添加最大循环次数或超时保护
