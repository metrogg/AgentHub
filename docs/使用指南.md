# AgentHub 使用指南

> 当前版本的核心体验是“群聊主线 + Orchestrator 动态计划 + 真实任务子对话 + `.agenthub/workdirs` 工作目录 + `.agenthub/handoff` 产物交接”。如果你看到旧的 `workspace-agent-child`、固定模板或静态兜底提示词，那不是现在的主路径。

## 一、环境准备

### 1. 安装 Bun
AgentHub 基于 Bun 运行时，请先安装 Bun >= 1.1.0：

```bash
# Windows (PowerShell)
powershell -c "irm bun.sh/install.ps1 | iex"

# macOS / Linux
curl -fsSL https://bun.sh/install | bash
```

### 2. 克隆项目并安装依赖

```bash
cd AgentHub
bun install
```

### 3. 配置环境变量

```bash
cp .env.example .env
```

编辑 `.env` 文件，至少配置以下项：

```env
# 必需：LLM API Key（至少配置一个供应商）
OPENAI_API_KEY=sk-xxxxxxxxxxxxxxxxxxxxxxxx
# 或
ANTHROPIC_API_KEY=sk-ant-xxxxxxxxxxxxxxxx

# 可选：如果使用第三方兼容 API（如 DeepSeek、SiliconFlow）
LLM_API_KEY=sk-xxxxxxxx
LLM_BASE_URL=https://api.deepseek.com/v1
LLM_MODEL=deepseek-chat
```

> 服务端启动后会自动把配置写入数据库 `settings` 表，后续可通过前端界面修改。

### 4. 初始化数据库

```bash
bun run db:migrate
```

## 二、启动项目

### 开发模式（推荐）

```bash
# 同时启动服务端 + 前端
bun run dev
```

- 服务端: http://localhost:8000
- 前端: http://localhost:5173
- 自动热重载

### 体验路径

1. 先在左侧创建或打开一个群聊。
2. 在群聊里直接描述复杂任务。
3. 交给 Orchestrator 后，先看任务看板和计划。
4. 执行时进入每个 Agent 的子对话查看真实过程。
5. 产物会在主群聊和任务看板里同步展示。

### 单独启动

```bash
# 仅服务端（带 --watch）
bun run dev:server

# 仅前端
bun run dev:web
```

### Docker 启动（可选）

```bash
docker compose up
```

## 三、基础使用流程

### 1. 单聊（Direct Session）

打开前端 http://localhost:5173，左侧栏点击 **"新建会话"**，输入消息即可与默认 LLM Agent 对话。

支持的功能：
- Markdown / 代码高亮渲染
- WebSocket 流式回复，可中途取消
- 消息编辑与重新生成

### 2. 群聊（Agent Group）

#### 创建 Workspace

1. 左侧栏点击 **"新建项目"**
2. 输入项目名称和目标（如 "开发一个登录页面"）
3. 系统会自动创建一个 Workspace 和默认 Agent Group

#### 在群聊中 @Agent

在群聊中输入 `@Agent名 你的问题`，消息会路由到指定 Agent 的子会话。

#### 创建自定义 Agent

在群聊中输入：
```
创建一个 Codex 前端实现 Agent，允许读取和写入 workspace
```

系统会生成 Agent 草案卡片，点击确认后即可加入当前 Agent Group。

## 四、Orchestrator 调度（核心功能）

### 触发方式

在群聊中输入：
```
@orchestrator 写一个带表单验证的登录页面
```

### 执行流程

1. **生成 Plan**：Orchestrator 调用 LLM 分析目标，生成 Task DAG（如：规划 → 实现 → 审查）
2. **确认 Plan**：前端展示任务卡片，可查看/调整任务分配
3. **点击 Dispatch**：创建 Workspace、分配 Agent、启动并发调度
4. **执行中**：
   - 各 Agent 在独立 Git 分支上并行执行（max 3 并发）
   - 失败任务自动重试（最多 2 次）
   - 重试失败后降级到 fallback Agent
5. **汇总**：所有任务完成后，LLM 智能聚合各 Agent 产出，生成统一报告发到群聊
6. **冲突处理**：如多 Agent 修改同一文件，自动检测冲突并尝试 LLM 合并

### 查看进度

任务执行过程中，可通过后端日志或数据库查看状态：

```bash
# 查看 workspace_tasks 状态
sqlite3 storage/agenthub.db "SELECT id, title, status, agent_id, attempt_count FROM workspace_tasks;"

# 查看 orchestrator_runs
sqlite3 storage/agenthub.db "SELECT id, status, summary_message_id FROM orchestrator_runs;"
```

## 五、Code Agent 配置

### 前提条件

确保本机已安装至少一个 Code Agent CLI 工具：

```bash
# Codex (OpenAI)
npm install -g @openai/codex

# Claude Code (Anthropic)
npm install -g @anthropic-ai/claude-code

# OpenCode
npm install -g @opencodeai/opencode
```

### 检测与配置

1. 前端打开 **设置 → 代码工具**，系统会自动探测本机已安装的 CLI
2. 点击对应工具的 **"配置"** 按钮，输入 API Key
3. 创建 Agent 时选择 `runtimeType: code-agent` 和对应的 `codeAgentType`

### 沙箱策略

在 Agent 设置中选择沙箱级别：

| 策略 | 说明 | 适用场景 |
|------|------|---------|
| `read-only` | 只读取文件，不切 Git 分支 | 代码审查、文件分析 |
| `workspace-write` | 切独立分支，执行后提取 diff | 代码生成、重构 |
| `danger-full-access` | 同样分支隔离，允许更多操作 | 需要修改配置文件的复杂任务 |

## 七、常见问题

### Q: 启动后前端显示 "无法连接到服务器"

检查：
1. 服务端是否启动（`bun run dev:server`）
2. `.env` 中的 `CORS_ORIGIN` 是否包含前端地址（默认 `http://localhost:5173`）
3. 浏览器控制台是否有 CORS 错误

### Q: Agent 回复 "API Key 未配置"

检查：
1. `.env` 中是否配置了至少一个供应商的 API Key
2. 前端设置中的模型配置是否保存成功
3. 服务端日志中的 `redactSensitive` 是否脱敏了 Key（正常现象）

### Q: Code Agent 没有实际执行代码

检查：
1. Agent 的 `runtimeType` 是否为 `code-agent`
2. 本机是否安装了对应的 CLI 工具（`codex` / `claude` / `opencode`）
3. `ENABLE_LOCAL_CLI_PROBES` 是否为 `true`
4. Agent 的 `sandboxPolicy` 是否为 `workspace-write` 或 `danger-full-access`

### Q: Git 分支隔离没有生效

检查：
1. Workspace 是否绑定了本地项目路径（`projectPath`）
2. Agent 的 `sandboxPolicy` 是否为非 `read-only`
3. 项目目录是否为有效的 Git 仓库（有 `main` 或 `master` 分支）

## 八、开发调试

### 查看服务端日志

```bash
bun run dev:server
# 日志输出在终端，包含请求路由、Agent 执行状态、Git 分支操作等
```

### 数据库调试

```bash
bun run db:studio
# 打开 Drizzle Studio，可视化查看和编辑所有表
```

### 运行测试

```bash
bun test
# 冒烟测试覆盖：API、调度、Git 分支、冲突检测等
```

### 手动测试 Orchestrator 完整链路

```bash
# 1. 创建群聊会话
curl -X POST http://localhost:8000/api/sessions \
  -H "Content-Type: application/json" \
  -d '{"title": "Test Group", "type": "group"}'

# 2. 发送 @orchestrator 消息触发 plan
curl -X POST http://localhost:8000/api/messages/{sessionId}/orchestrator-plan \
  -H "Content-Type: application/json" \
  -d '{"content": "@orchestrator 写一个登录页面"}'

# 3. 点击 dispatch（或通过 API 调用）
# 见 messages.ts 中的 dispatch endpoint
```

## 九、比赛演示建议

### 推荐 Demo 场景

1. **基础对话**：单聊展示 Markdown 渲染、流式回复、取消功能
2. **Agent Group**：创建 Workspace，展示群聊中 @Agent 的能力
3. **Orchestrator 调度**：`@orchestrator 写一个带表单验证的登录页面`
   - 展示 Task DAG 生成
   - 展示并发执行（多个 Agent 同时工作）
   - 展示 Git 分支隔离（`git branch` 查看临时分支）
   - 展示 LLM 聚合汇总
4. **Code Agent 执行**：`@Codex 给登录页面加上记住密码功能`
   - 展示真实代码生成
   - 展示 diff 提取和冲突检测

### 演示前检查清单

- [ ] `bun run typecheck` 通过
- [ ] `bun test` 全部通过
- [ ] LLM API Key 配置正确（提前测试连接）
- [ ] 至少安装一个 Code Agent CLI（推荐 Codex）
- [ ] 准备一个本地 Git 仓库作为测试项目
- [ ] 清理 `storage/agenthub.db` 避免旧数据干扰
