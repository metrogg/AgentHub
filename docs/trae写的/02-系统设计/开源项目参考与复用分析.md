## 1. 策略概述

AgentHub 的构建策略是 **"善用开源、聚焦核心"**：

- **约 60% 的功能**可直接复用成熟的开源 npm 包或 CLI 工具
- **约 40% 的核心编排逻辑**需要自研（Orchestrator、Harness 引擎、Memory 系统）

这条分界线非常关键——重复造轮子的部分交给开源社区，体现架构深度和创新思考的部分由我们实现。

## 2. IM 聊天交互层

| 项目 | 仓库 | 语言 | 复用方式 | 成熟度 |
|------|------|------|----------|--------|
| 虾饺IM (Xiajiao) | 开源社区 | Node.js | **参考架构 + 改造** | ⭐⭐⭐ |
| OpenClaw Gateway | github.com/nicepkg/openclaw | TypeScript | 参考适配器模式 | ⭐⭐⭐⭐ |
| HiClaw | github.com/alibaba/higress | Go+Matrix | 参考透明协作范式 | ⭐⭐⭐ |
| AgentScope | github.com/modelscope/agentscope | Python | 参考@提及机制 | ⭐⭐⭐ |

### 🔥 重点：虾饺IM — 最适合的 IM 层参考

虾饺IM 是最适合 AgentHub 参考的项目，理由如下：

**架构契合点**：
- **极限轻量**：仅 6 个核心 npm 包（`ws`、`formidable` 等）+ Node.js 标准库，与我们的最小依赖原则一致
- **原生群聊 + @机制**：`@角色名` 触发定向对话，与我们设计的 @指令解析完全吻合
- **完整数据流**：消息持久化 → WebSocket 广播 → @解析 → 加载角色 → 记忆检索 → LLM 工具循环 → 流式回复

**可直接复用的部分**：
- WebSocket 连接管理逻辑（建立→认证→心跳→断开→重连）
- @指令解析正则（`/@([\w\u4e00-\u9fa5-]+)/g`）和路由逻辑
- 消息持久化 Schema 设计
- 流式回复的 SSE/WS 推送模式

**需要改造的部分**：
- SQLite → PostgreSQL + pgvector（关系升级 + 向量检索）
- 单一 LLM 调用 → Orchestrator + 多 Agent 适配器
- 简单角色记忆 → 三层 Memory 系统（Working/Session/Long-term）

| 项目 | 仓库 | 语言 | 复用方式 | 成熟度 |

| AutoGen / AG2 | github.com/microsoft/autogen | Python | 参考多Agent对话 | ⭐⭐⭐ |

### 🔥 重点：Claude Code 开源架构 — 自研 Harness 的蓝本

Claude Code 的**开源 SDK 和 MCP Server 部分**揭示了核心架构，我们的模块设计已完整参考：

**Agent Loop — AsyncGenerator 模式**：
```
16步迭代管线：
技能发现预取 → 工具结果预算 → Snip Compact → Micro Compact
→ Context Collapse → Auto Compact → 阻塞限制检查 → ★ 调用 Agent API
→ 流式工具执行 → 后采样 Hooks → 中断处理 → 停止 Hooks
→ Token 预算检查 → 附件消息注入 → MCP 工具热更新 → transition追踪
```

**Tool Registry — Fail-Closed 设计**：
```typescript
// 默认值策略：任何遗漏配置 = 不安全
const TOOL_DEFAULTS = {
  isConcurrencySafe: () => false,   // 默认串行
  isReadOnly: () => false,          // 默认需要权限
  isDestructive: () => false,
  checkPermissions: (input) => ({ behavior: 'allow', updatedInput: input }),
}
```

**四级上下文压缩管道**：完整移植 Snip（零API）→ Micro（缓存编辑）→ Collapse（读时投影）→ Auto（LLM摘要）设计。

**Claude Code MCP SDK 可直接安装使用**：
```bash
bun add @modelcontextprotocol/sdk
```

| OpenHands | github.com/All-Hands-AI/OpenHands | Python | 参考 Docker 沙箱 | ⭐⭐⭐ |

### 🔥 重点：Codex CLI — 可直接作为 Agent 后端

**Codex CLI 是 OpenAI 开源的 TypeScript CLI Agent**，是 AgentHub 最重要的集成目标：

- **语言完全匹配**：TypeScript，可在同一 Bun 进程内通过 `Bun.spawn` 调用
- **npm 包可用**：`@openai/codex`，CLI 命令 `codex exec --json`
- **代码编辑能力**：原生支持文件读写、命令执行
- **MCP 支持**：支持 Model Context Protocol

**集成方式（已在模块设计中定义）**：
```typescript
// 通过 Bun.spawn 调用 Codex CLI
const codex = Bun.spawn(['codex', 'exec', '--json'], {
  stdin: 'pipe',
  stdout: 'pipe',
})

// 流式解析 JSON 行输出
for await (const line of codex.stdout) {
  const event = JSON.parse(line)
  yield convertCodexEvent(event)
}
```

### Claude Code 的集成路径

Claude Code 的完整源码不公开，但有两条集成路径：

1. **Claude API**：通过 `@anthropic/sdk` 直接调用 Claude 模型（需要 API Key）
2. **Claude Code MCP Server**：通过 MCP 协议暴露其工具能力，我们通过 `@modelcontextprotocol/sdk` 桥接

**比赛 Demo 建议**：
- **主力适配 Codex CLI**（完整开源，零成本集成）
- **架构预留 Claude API 适配器**（API Key 需要，但接口已设计好）

## 5. 代码 Diff / Git 操作

| 项目 | 仓库 | 复用方式 | 成熟度 |
|------|------|----------|--------|
| simple-git | github.com/steveukx/git-js | **直接安装** | ⭐⭐⭐⭐⭐ |
| diff | github.com/kpdecker/jsdiff | **直接安装** | ⭐⭐⭐⭐⭐ |
| monaco-editor | github.com/microsoft/monaco-editor | **前端 Diff 展示** | ⭐⭐⭐⭐⭐ |

### 三个库一站式解决 Git 操作 + Diff

```bash
bun add simple-git diff monaco-editor
```

| 库 | 用途 | 关键 API |
|-----|------|----------|
| `simple-git` | Git 操作封装 | `addWorktree()`, `diff()`, `branch()`, `merge()`, `checkIsRepo()` |
| `diff` | Diff 文本生成 | `createTwoFilesPatch()`, `createPatch()`, `structuredPatch()` |
| `monaco-editor` | 前端可视化 | `MonacoDiffEditor` 组件，支持语法高亮、内联/并排视图 |

**不需要自己实现的东西**：
- ❌ 自己写 git 命令的 spawn 封装 → ✅ 用 `simple-git`
- ❌ 自己实现 Myers 差分算法 → ✅ 用 `diff` 的 `structuredPatch()`
- ❌ 自己写 Diff 渲染组件 → ✅ 用 `monaco-editor` 的 `DiffEditor`

## 6. 网页预览沙箱

| 项目 | 仓库 | 复用方式 | 成熟度 |
|------|------|----------|--------|
| Sandpack | github.com/codesandbox/sandpack | **直接安装** ⭐推荐 | ⭐⭐⭐⭐⭐ |
| WebContainer | webcontainer.io | Phase 2 升级方案 | ⭐⭐⭐⭐ |

### 🔥 重点：Sandpack — 比 iframe+srcdoc 更好的方案

之前架构设计中使用 iframe+srcdoc 自己组装预览。**Sandpack** 提供了更完整的浏览器内代码预览方案，由 CodeSandbox 团队维护：

```bash
bun add @codesandbox/sandpack-react
```

**Sandpack 对比自研 iframe 方案**：

| 能力 | 自研 iframe | Sandpack |
|------|------------|----------|
| 多文件项目 | 需自己组装 HTML | ✅ 内置模板系统 |
| HMR 热更新 | 需自己实现 | ✅ 开箱即用 |
| 安全隔离 | 手动配置 sandbox | ✅ 内置沙箱 |
| TypeScript 支持 | ❌ 无法编译 | ✅ 浏览器内编译 |
| 依赖安装 | ❌ 不支持 | ✅ 支持 npm 包 |
| 视口切换 | 需自己实现 | ✅ 内置 Responsive |
| 代码量 | ~200 行 | ~20 行 |

> **建议**：MVP 直接使用 Sandpack，将省下的时间投入到 Orchestrator 和 Harness 引擎的开发。

**Sandpack 集成示例**：
```tsx
import { Sandpack } from '@codesandbox/sandpack-react'

<Sandpack
  template="react"
  files={{
    '/App.tsx': agentGeneratedCode,
    '/styles.css': agentGeneratedCss,
  }}
  options={{ showNavigator: true, showTabs: true }}
/>
```

## 10. 必须自研的部分

以下核心差异化能力无法用开源替代，也是比赛评审的关注重点：

### 10.1 Orchestrator 任务编排

> **理由**：五项决策权独占（任务生命周期、执行计划裁决、Agent 路由、失败处理、硬终止条件）是 AgentHub 核心创新，没有任何开源框架能直接满足。

**自研关键点**：
- 声明式 DAG 计划格式（JSON）
- 并行步骤检测算法
- 四级失败降级（RETRY→FALLBACK→SKIP→ABORT）
- 四道硬闸限制（max_steps/max_tokens/max_duration/max_tool_calls）

### 10.2 Harness 引擎核心

> **理由**：四级上下文压缩管道、Token Budget 熔断、Fail-Closed Tool Registry 体现架构深度。参考 Claude Code 的架构思想，但所有代码需要我们手写。

**自研关键点**：
- 16 步 AsyncGenerator Agent Loop
- Tool Registry 九项元信息 + Fail-Closed 默认值
- 四级压缩管道的触发条件和实现
- Budget Controller 四区降级模型

### 10.3 Memory 系统

> **理由**：三层记忆架构（Working/Session/Long-term）+ 基于访问频次 × 时间 × 重要性的遗忘机制是差异化能力。虽然 pgvector 是开源的，但记忆管理逻辑需要自研。

**自研关键点**：
- Episodic Memory（事件记忆）+ Semantic Memory（语义记忆）双模式
- 混合注入策略（前置注入 + memory_search 工具）
- 多维保留分数计算和多阈值遗忘三态

### 10.4 IM @指令与 Orchestrator 联动

> **理由**：@指令解析虽参考虾饺IM，但与 Orchestrator 的深度联动（@Agent → 路由 → DAG 计划 → Agent 调度 → 流式返回）是独特的业务逻辑。

**自研关键点**：
- @指令解析器 + Agent 注册表匹配
- 语义路由（能力匹配 + 负载均衡 + 质量评分 + 优先级排序）
- 流式响应推送到 IM 界面的打字机效果
