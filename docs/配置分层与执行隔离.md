# 配置分层与执行隔离

本文档定义 AgentHub 当前关于配置与执行隔离的统一口径。

## 三层配置真相

### 模型管理

职责：

- 维护模型目录
- 保存双端点和密钥
- 执行模型连通性测试

不负责：

- 决定某个专家 Agent 使用哪个 CLI
- 决定某个专家 Agent 的沙箱
- 维护 CLI 平台原生配置

### Coding Tools

职责：

- 检查 Codex CLI / Claude Code / OpenCode / Gemini CLI 是否安装
- 检查这些 CLI 的原生认证状态
- 展示原生 config/auth 文件状态
- 展示 Docker Sandboxes 是否 ready
- 保存 CLI 平台级参数

不负责：

- 选择模型
- 保存通用 base URL / api key / protocol 作为运行时真相
- 决定具体 Agent 的组合装配

### Agent 配置

职责：

- 选择 `codeAgentType`
- 绑定 `modelId`
- 绑定 `skillIds / MCP / toolPermissions`
- 选择 `sandboxPolicy`

这是唯一允许装配 `code agent × model × skills × sandbox` 组合的地方。

## 内部 LLM 默认模型

系统保留一个单独可见的 `内部 LLM 默认模型`。

它只影响：

- 欢迎页动态提示
- Orchestrator
- Planner
- Synthesizer
- 其他内部 LLM fallback 路径

它不影响：

- 专家 Agent 的 CLI × 模型组合
- Coding Tools 页面的平台状态

## Docker Sandboxes 状态语义

设置页和健康检查需要区分这些状态：

- `providerConfigured`
- `sbxInstalled`
- `daemonReady`
- `dockerLoggedIn`
- `policyConfigured`
- `sandboxRunnable`
- `supportsPerAgentIsolation`
- `cleanupMode`
- `sandboxRoot`

解释：

- `sbxInstalled=true` 只表示 CLI 存在
- `daemonReady=true` 只表示 daemon 可通信
- `dockerLoggedIn=true` 只表示 Docker 登录可用
- `policyConfigured=true` 只表示默认网络策略已配置
- `sandboxRunnable=true` 才表示 Docker Sandboxes 当前真的能跑
- `supportsPerAgentIsolation=true` 才表示每个 Agent 的运行态真正可隔离

## Code Agent 沙箱口径

Code Agent 当前用户可选沙箱只保留：

- `workspace-write`
- `danger-full-access`

`read-only` 不再作为公开的 code-agent 配置项。

如果要表达研究/审查/低风险语义，应通过角色职责、工具权限、上下文策略和审批策略来完成，而不是让 CLI 再走一条历史 `read-only` 分支。

## 每 Agent 独立运行态

默认目标是：每个 Agent 都是独立执行单元。

至少要隔离：

- `HOME / USERPROFILE`
- `APPDATA / LOCALAPPDATA`
- `TMP / TEMP / TMPDIR`
- `XDG_CACHE_HOME / XDG_CONFIG_HOME / XDG_DATA_HOME`
- npm/bun cache
- CLI config / session / temp 文件

这也是为什么 `docker-sandbox` 是默认隔离层，`local-workdir` 只能作为兼容降级路径。
