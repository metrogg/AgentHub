# Telegram 风格移动端设计提取

本文档基于用户提供的 Telegram 安卓截图提取设计风格，并映射到 AgentHub 安卓端改造。目标不是逐像素复制 Telegram，而是复用其移动 IM 的视觉秩序：深色、紧凑、圆润、可扫读、主操作清晰。

## 截图观察

### 设置页

- 顶部深蓝黑大面积留空，头像居中放大，名称和账号信息居中。
- 功能入口是设置列表式布局：彩色圆角图标 + 白色标题 + 灰蓝副标题。
- 底部导航是悬浮半透明胶囊，选中项有蓝色圆角高亮。
- 下载条这类系统状态固定贴底，颜色用明亮 Telegram 蓝。

### 通讯录页

- 标题很大，搜索框是深色圆角胶囊。
- 空状态居中：插画、标题、说明、蓝色主按钮。
- 邀请列表放进深色圆角面板，头像用高饱和圆形色块。
- 列表文字层级明确：标题白色，说明灰蓝，按钮蓝色。

### 会话列表

- 会话行没有卡片边框，靠头像、文字、时间和未读角标形成层级。
- 头像 48dp 到 56dp，圆形，颜色丰富但不刺眼。
- 搜索框紧贴标题下方，列表信息密度高。
- 新建入口是右下角蓝色圆形悬浮按钮。

### 对话页

- 顶栏紧凑：返回、头像、标题、在线状态、右上角菜单。
- 聊天背景是深色底纹，不是纯色白底。
- 用户气泡靠右，蓝紫或蓝色；对方气泡靠左，深色卡片。
- 气泡圆角较大，但靠近头像的一角更小，形成聊天方向感。
- 输入框是底部悬浮胶囊：工具按钮、表情、输入、附件、语音或发送。

### 右上角菜单

- 菜单是深色浮层，圆角明显。
- 常规动作白色，危险动作红色。
- 动作收纳到菜单中，主界面不堆按钮。

## 设计语义

### 色彩

- 页面背景：`#121B24`
- 聊天背景：`#0D1620`
- 普通面板：`#1B2530`
- 抬升面板：`#22303D`
- 搜索框和输入框：`#22303F`
- 分割线：`#253343`
- 主文字：`#F4F7FA`
- 次文字：`#92A0AE`
- Telegram 蓝：`#4EA2F6`
- 蓝色选中底：`#223648`
- 成功绿色：`#55D66B`
- 危险红：`#FF6B78`
- 用户气泡：`#4B83E4`
- Agent 气泡：`#1D2834`
- 底部胶囊：`#E616212D`，带轻微透明感。

### 排版

- 列表页标题：24sp 左右，粗体。
- 对话页标题：18sp 左右，半粗体。
- 列表主标题：16sp，半粗体。
- 列表副标题：14sp，灰蓝色。
- 气泡正文：15sp 到 16sp，行高 21sp 到 22sp。
- 不使用负字距，不做夸张大标题。

### 圆角和间距

- 头像使用圆形。
- 搜索框、输入框和底部导航使用 24dp 到 28dp 胶囊圆角。
- 普通面板使用 12dp 到 16dp 圆角。
- 列表行高度保持紧凑，横向间距 14dp 到 16dp。
- 底部导航和输入框必须避开系统导航栏和软键盘。

## AgentHub 安卓端改造规则

### 主壳

- 全局主题切到深色 Telegram 风格。
- 顶部保留大标题列表页和紧凑对话页两种形态。
- 右上角入口统一收纳：列表页放发起群聊、扫一扫、同步；对话页放设置、回到列表、归档、删除、同步。

### 底部导航

- 固定四个入口：消息、通讯录、工作台、设置。
- 使用悬浮半透明胶囊，不贴死屏幕底部。
- 当前 tab 用蓝色文字和浅蓝底高亮。

### 会话列表

- 保留搜索框、归档切换、新建会话浮动按钮。
- 会话行使用圆形头像、标题、预览、时间。
- 归档和删除同时支持长按菜单和右侧更多按钮。
- 删除必须二次确认。

### 对话页

- 使用深色聊天底纹。
- 用户消息靠右蓝色气泡，Agent 消息靠左深色气泡。
- 流式输出时在 Agent 气泡内显示状态条：正在输入或正在生成产物。
- 删除两个快速对话卡片，只保留欢迎语。
- 输入框使用底部悬浮胶囊，并使用 `imePadding` 与 `navigationBarsPadding` 规避软键盘重叠。

### 快速预览

- Agent 产物在消息气泡内显示“快速预览”条目。
- HTML/网页可直接内嵌 WebView 预览。
- 图片可用 WebView 打开预览。
- Word、PPT、PDF、Excel 等文档显示摘要占位，并提供系统外部预览入口。
- Diff 和工作流产物在移动端直接展示摘要文本。

### 通讯录

- 使用 Telegram 式搜索框和字母分组。
- 联系人头像使用稳定的彩色圆形色块。
- 只展示真实同步到的 Agent 通讯录，不展示重复占位。

### 工作台和二级页

- 工作台采用设置页式列表，而不是营销卡片堆叠。
- 模型管理、Coding Tools、Skills 市场、办公室统一深色面板。
- 二级页继续使用同一套色彩和圆角体系，不能退回白底。

## 设计边界

- 不使用花哨渐变、光斑、装饰性大插画堆叠。
- 不把所有功能暴露成一屏按钮，优先用菜单和列表收纳。
- 不恢复固定场景模板入口。
- 不把移动端做成桌面端缩小版；移动端优先服务“看状态、发消息、预览产物、轻量管理”。

## Kimi 原型可吸收点

用户补充的原型页更偏 AgentHub 自身业务，而不是纯 IM 复刻。可吸收的部分如下：

- Agent 色彩体系：Claude Code、Codex、OpenCode、Orchestrator 等 Agent 可使用稳定品牌色，头像用浅色底 + 彩色描边，方便在群聊里快速识别发言来源。
- 对话消息组件化：普通文本之外，需要支持代码块、审批卡、部署进度、产物卡、系统提示等结构化消息。
- 审批体验：待确认的代码变更、部署、权限申请应当以卡片呈现，突出“查看详情 / 确认 / 拒绝”。如果移动端暂时没有确认接口，至少要显示“待复核”状态和摘要，避免流式输出像普通文本一样被忽略。
- 产物预览：产物卡要比普通附件更强，展示标题、类型、摘要和点击预览入口。网页、HTML、图片优先内嵌预览，Office 文档给系统预览入口。
- 底部 Sheet：新建对话、选择 Agent、附件入口适合做成底部抽屉，不应挤在输入栏或顶栏。
- 代码输出：移动端要用等宽字体、深色代码块、语言标签和“桌面端查看完整代码”的提示，避免长代码直接撑爆聊天气泡。
- 部署/执行进度：多步骤任务适合用进度条或步骤列表展示，颜色区分 running、done、failed、reviewRequired。

当前落地策略：保留 Telegram 的深色 IM 外壳和底部胶囊导航；吸收 Kimi 原型的 AgentHub 业务组件，尤其是代码块、Code Agent 状态卡、产物预览卡和后续审批 Sheet。
