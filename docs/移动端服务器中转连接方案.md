# 移动端服务器中转连接方案

## 结论

移动端与桌面客户端不再优先采用局域网直连，而是改为通过 AgentHub Server 中转连接。

新的连接模型：

```text
Android / iOS / Web Mobile
        |
        | HTTPS + WebSocket
        v
AgentHub Server / Relay
        |
        | HTTPS + WebSocket
        v
Desktop Client / Local Agent Runtime
```

手机端只做轻量交互：会话列表、消息发送、审批确认、产物预览、任务状态查看。桌面端继续负责本地项目访问、CLI Code Agent、模型密钥、本地沙箱和产物生成。服务器负责账号、设备配对、消息同步、事件转发和离线状态。

## 为什么改

当前局域网直连方案的限制比较明显：

- 手机和电脑必须在同一 Wi-Fi 或局域网。
- Windows 防火墙、路由器隔离、校园网/公司网都会影响连接。
- 二维码里暴露的是本机局域网地址，换网络后立即失效。
- 多设备、离线通知、远程审批和跨网络使用都很难自然支持。

服务器中转后：

- 手机可以在任意网络访问同一个 AgentHub 账号。
- 桌面端只需要主动连服务器，不需要暴露本机端口。
- 配对二维码只包含一次性 pairing code，不包含本机 IP。
- 后续可以自然扩展推送通知、多端同步、设备管理和远程审批。

## 目标职责划分

### Server

- 管理用户账号、设备、会话、消息和 workspace 元数据。
- 提供 REST API 加载会话、消息、任务、产物和设置。
- 提供 WebSocket 通道转发实时事件。
- 维护设备在线状态和路由表。
- 生成并校验一次性配对码。
- 将手机端命令转发给在线桌面端。
- 将桌面端 Agent 事件广播给手机端和 Web 端。

### Desktop Client

- 登录用户账号并注册为 `desktop` 设备。
- 与 Server 建立长连接。
- 接收来自 Server 的执行请求、审批响应和取消指令。
- 在本地执行 Code Agent、读取项目文件、生成 diff 和产物。
- 将 Agent 流式输出、任务状态、产物元数据回传 Server。

### Mobile Client

- 登录或扫码配对到用户账号。
- 连接 Server，而不是连接桌面端局域网地址。
- 发送消息、审批、取消、继续任务等轻量命令。
- 接收 Server 推送的流式消息、任务状态和产物更新。

## 配对流程

推荐流程：

1. 桌面端登录 Server。
2. 桌面端请求 `POST /api/devices/pairing-codes` 生成一次性二维码。
3. Server 返回 `pairingCode`、`expiresAt` 和二维码 payload。
4. 手机端扫码，向 Server 调用 `POST /api/devices/pair`。
5. Server 校验 pairing code，绑定手机设备到同一账号。
6. 手机端保存 device token，以后直接连接 Server。

二维码 payload 示例：

```json
{
  "version": 2,
  "serverUrl": "https://agenthub.example.com",
  "pairingCode": "pair_xxx",
  "expiresAt": "2026-05-26T12:00:00.000Z"
}
```

注意：二维码不再包含 `baseUrl: http://192.168.x.x:8000` 这类本机地址。

## WebSocket 事件路由

所有端统一连接：

```text
wss://agenthub.example.com/ws
```

连接建立后发送设备注册事件：

```json
{
  "type": "device:hello",
  "payload": {
    "deviceId": "device_xxx",
    "deviceType": "desktop"
  }
}
```

常用事件：

- `session:join`: 加入会话房间。
- `message:created`: 新消息已写入。
- `message:stream`: Agent 流式输出片段。
- `message:completed`: Agent 回复完成。
- `task:update`: workspace task 状态变化。
- `approval:requested`: 需要用户审批。
- `approval:resolved`: 审批已处理。
- `desktop:command`: Server 转发给桌面端的本地执行命令。
- `desktop:result`: 桌面端回传执行结果。

## 数据表建议

新增或扩展：

- `devices`
  - `id`
  - `user_id`
  - `type`: `desktop` | `mobile` | `web`
  - `name`
  - `token_hash`
  - `last_seen_at`
  - `created_at`
- `device_pairing_codes`
  - `code_hash`
  - `user_id`
  - `desktop_device_id`
  - `expires_at`
  - `consumed_at`
- `device_events`
  - 可选，用于审计关键审批和远程命令。

## 迁移落地顺序

1. 保留当前局域网直连作为开发备用通道。
2. 增加 Server 侧设备表、配对码表和 device token 鉴权。
3. 将二维码 payload 从局域网 `baseUrl` 改成 `serverUrl + pairingCode`。
4. Android `ConnectionConfig` 改为保存 `serverUrl`、`deviceId`、`authToken`。
5. 桌面端启动后主动注册设备并保持 WebSocket 在线。
6. Server 增加设备路由，将手机端命令转发给在线桌面端。
7. 消息、任务、审批统一走 Server 存储和广播。
8. 稳定后隐藏局域网手动连接入口，仅保留高级调试入口。

## MVP 范围

第一版不要急着做完整云协作，先完成“单用户、多设备、中转连接”：

- 一个用户账号。
- 一个在线桌面端。
- 多个手机端可同时连接。
- 手机端可以看会话、发消息、接收流式输出。
- 本地执行仍发生在桌面端。
- 桌面端离线时，手机端显示不可执行，但仍可查看历史消息。

这样可以快速解决局域网连接不稳定的问题，同时不把本地 Code Agent 的安全边界扩大到手机端。
