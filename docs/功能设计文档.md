## 1. 产品定位

AgentHub 是一个 **IM 风格的多 Agent 协作平台**。

核心交互范式：

1. 用户从群聊发起请求
2. Orchestrator 分析请求，生成动态任务 DAG
3. 多个 Agent 在各自的子会话中接收具体任务
4. 主群聊展示编排进度、成员报告、制品卡片和最终综合结果
5. 用户可打开子会话查看每个 Agent 的真实执行轨迹

**不是**固定场景模板驱动，**不是**静态角色路由。平台保持通用优先，所有任务分解来自模型动态生成。

## 2. 核心概念

### 2.1 会话模型

| 会话类型 | metadata.kind | 说明 |
|---|---|---|
| Agent 私聊 | `agent-direct` | 用户与单个 Agent 的一对一对话 |
| 群聊 | `group` | 用户与多个 Agent 的工作群 |
| 任务子会话 | `orchestrator-task` | 群聊下由编排器创建的任务执行会话 |

### 2.2 Agent 身份模型

只有两种运行时类型：

- **code-agent**：绑定 CLI 工具（Codex / Claude Code / OpenCode / Gemini），可读写文件、执行命令
- **llm**：纯 LLM 对话，用于规划、分析、总结等不需要文件操作的任务

A2A、MCP、Skills、Rules 是协议或能力层，**不是** Agent 运行时类型。

### 2.3 工作目录

```
{projectRoot}/.agenthub/
  workdirs/{runId}/{agentName}/{taskId}/   ← Agent 执行目录
  handoff/{runId}/{taskId}/                ← 上游制品交接目录
```

- 写入型 Agent 在 `.agenthub/workdirs/...` 中执行
- 只读型 Agent 可读取项目根目录
- 上游制品复制到 `.agenthub/handoff/...` 供下游使用
- 未选择项目时，自动创建工作区到系统用户数据目录

## 3. IM 聊天系统

### 3.1 欢迎页

- 打字机效果标题「有什么可以帮忙的？」
- 快速对话气泡：100 条预置内容，seed 随机打乱，每次展示 10 条
- 两行布局：上行 4 条（标准尺寸），下行 6 条（紧凑尺寸，50% 宽度居中）
- 无限水平滚动动画，hover 暂停
- 两侧渐隐遮罩（20%）
- 工作区快速选择：搜索、打开本地文件夹、新建

### 3.2 直接对话

- 选择一个 Agent 进入私聊
- 消息发送后由对应 Runtime 执行（LLM 或 Code Agent）
- 支持 Markdown、代码块、diff 渲染
- WebSocket 实时流式输出，支持取消
- 消息编辑和重新生成

### 3.3 群聊

- 多 Agent 工作群，绑定一个工作区
- 用户发送请求后，Orchestrator 判断复杂度：
  - 简单问题 → Orchestrator 直接回复
  - 复杂任务 → 创建动态计划 + 任务看板
- @mention 自动补全：输入 `@` 弹出 Agent 列表面板
- /skill 命令面板：输入 `/` 弹出可用 Skill 列表
- 群聊标题：头像 + 群名 (人数)

### 3.4 任务子会话

- 群聊下每个任务自动创建子会话（`orchestrator-task`）
- 子会话在侧边栏群聊树中展示，可点击打开
- 子会话内是 Agent 的完整执行轨迹

### 3.5 消息能力

| 能力 | 说明 |
|---|---|
| 流式输出 | WebSocket 推送，打字机效果 |
| 取消 | 运行中可中断 |
| 编辑 | 修改已发消息并重新执行 |
| 重新生成 | 对上一条回复重新生成 |
| 置顶 | 重要消息置顶 |
| 回复引用 | replyToMessageId 引用历史消息 |

### 3.6 侧边栏

- 会话树：Agent 私聊列表 + 群聊列表（含子会话展开）
- 搜索过滤
- 会话归档（带保留策略）
- 会话数量按树根节点统计

## 4. 多 Agent 协作编排

### 4.1 意图路由

`IntentRouter` 评估消息复杂度，自动判断是否需要编排：

- 多文件引用
- 多阶段关键词
- 架构意图
- 协作暗示
- 复杂动词
- 长消息

复杂度达标时自动触发编排流程。

### 4.2 计划生成

`Planner` 采用 Spec-first 策略：

1. 生成 `ProjectSpec`（项目规格）
2. 基于 Spec 生成 `ExecutionPlan`（执行计划）
3. 计划包含 **Phase → Task** 两级结构
4. 每个 Task 指定：依赖关系、分配 Agent、输入引用、输出键、并行组、超时、重试策略

### 4.3 澄清机制

计划生成后，Orchestrator 可提出 1-3 个澄清问题（带选项），等待用户回答后再执行。

### 4.4 任务调度

`TaskScheduler` 基于 DAG 调度：

- `TaskGraph`：拓扑排序、环检测、就绪任务发现
- `Semaphore(3)`：最多 3 个任务并行执行
- `AbortController`：支持取消传播
- `addTasksToRun()`：执行中途动态添加任务

### 4.5 执行生命周期

```
planning → running → synthesizing → completed
                ↘ failed / cancelled
```

12 阶段详细流程：intake → clarify → plan → confirm → dispatch → execute → collect → review → resolve → synthesize → deliver → archive

### 4.6 失败恢复

`ReplanningEngine` 提供 6 种恢复策略：

| 策略 | 说明 |
|---|---|
| `retry_with_backoff` | 指数退避重试 |
| `repair_output` | 修复输出格式 |
| `agent_substitution` | 替换失败 Agent |
| `local_replan` | 局部重新规划 |
| `task_split` | 拆分过大任务 |
| `fallback_to_orchestrator` | 回退到 Orchestrator 处理 |
| `escalate_to_user` | 上报用户决策 |

### 4.7 人工介入

- 计划确认：用户审批后才执行
- 运行取消：随时中断整个编排
- 任务重试：对失败任务手动重试
- 冲突解决：文件冲突时人工选择方案

### 4.8 结果综合

`Synthesizer` 从 Blackboard 读取所有任务输出，生成最终交付报告。

### 4.9 任务看板

- DAG 可视化：Phase → Task 层级
- 状态标签：pending / running / done / failed / cancelled / blocked / skipped
- 进度百分比
- 制品卡片（diff / file / preview / deploy / log / workflow）
- 子会话链接

## 5. Agent 管理

### 5.1 角色预设

| 角色 | 职责 |
|---|---|
| orchestrator | 总协调，分解任务，分配执行 |
| clarifier | 澄清需求，消除歧义 |
| architect | 架构设计，技术选型 |
| researcher | 调研分析，信息收集 |
| coder | 编码实现，文件操作 |
| verifier | 验证测试，质量检查 |
| reviewer | 代码审查，改进建议 |
| integrator | 集成合并，冲突解决 |
| custom | 自定义角色 |

每个预设包含：默认系统提示、能力标签、工具权限、沙箱策略、接受的任务类型、产出的制品类型。

### 5.2 配置项

| 配置 | 说明 |
|---|---|
| 名称 / 角色 / 描述 | 基本信息 |
| 运行时类型 | code-agent 或 llm |
| Code Agent 类型 | codex / claude-code / opencode / gemini |
| 模型覆盖 | 可指定独立模型 |
| 系统提示 | 自定义行为指令 |
| 能力标签 | 用于任务匹配 |
| Skill 绑定 | 挂载特定 Skill |
| 工具权限 | 逐工具配置 |
| 沙箱策略 | read-only / workspace-write / danger-full-access |
| 上下文策略 | recent-only / pinned-recent / workspace-aware |
| 颜色 | UI 展示颜色 |
| 自动调用 | 是否自动参与 |
| 需要审批 | 执行前是否需要用户确认 |

### 5.3 协作关系

Agent 之间可定义 5 种关系：

- `handoff_to`：制品传递方向
- `reviewed_by`：审查关系
- `fallback_to`：失败降级
- `reports_to`：汇报关系
- `blocks`：阻塞依赖

### 5.4 对话式修改

在 Agent 配置页，可用自然语言描述修改意图，系统解析后自动更新配置。

## 6. Code Agent 执行

### 6.1 支持的 CLI 工具

| 工具 | 协议 | 说明 |
|---|---|---|
| Codex CLI | OpenAI Compatible / Responses | 支持 ChatGPT 设备认证 |
| Claude Code | Anthropic Messages | Anthropic 原生协议 |
| OpenCode | OpenAI Compatible | 开源 Code Agent |
| Gemini CLI | OpenAI Compatible | Google Gemini |

### 6.2 配置管理

- CLI 检测与自动安装
- 每工具独立配置：模型、API Key、Base URL、协议、沙箱策略
- 连接测试
- 环境变量和命令预览
- 执行启用/禁用开关
- Codex config.toml 和 auth.json 文件编辑
- OpenCode 本地模型读取

### 6.3 执行流程

```
TaskExecutionService
  → 准备 workdir（.agenthub/workdirs/{runId}/{agentName}/{taskId}/）
  → 生成 Agent Profile
  → 构建 A2A message/send 信封
  → LocalA2ATransport 本地传输
  → CodeAgentRuntime 执行 CLI
  → code-agent-adapter 协议翻译
  → 流式输出步骤事件
  → 收集制品
  → 执行验证命令
  → 写入 Blackboard
```

### 6.4 实时过程流

Code Agent 执行时持续推送步骤事件：

- 启动
- 读取/搜索文件
- 运行命令
- 创建/修改文件
- 错误输出
- 完成/失败

前端边运行边显示过程卡片，最新项带 loading 和流光动画。

## 7. Skills 与 Rules 系统

### 7.1 Skills（.skill.yml）

```yaml
name: code-review
description: 代码审查规则
prompt: |
  审查以下代码，关注：
  - 安全漏洞
  - 性能问题
  - 代码风格
variables:
  language: typescript
```

- YAML 格式定义
- 系统提示模板 + 变量插值
- 能力标签匹配
- LLM Runtime 和 Code Agent Runtime 分别注入

### 7.2 Rules（.yml）

- 约束规则：命名规范、禁止模式
- 作用于特定目录或文件类型
- 自动注入 Agent 系统提示

### 7.3 Spec 工作流（.spec.yml）

```yaml
name: code-review
trigger:
  patterns: ["审查", "review"]
phases:
  - name: analyze
    tasks: [...]
  - name: report
    tasks: [...]
synthesis: summary
```

- 定义触发模式、阶段 DAG、综合策略
- Planner 优先匹配 Spec，再走通用生成

### 7.4 SKILL.md 外部技能

- SkillHub 市场搜索与安装
- GitHub URL 安装
- npx 命令安装
- 本地扫描发现
- 评分匹配：基于能力标签和文本重叠

### 7.5 Skill 注入路径

- LLM Runtime：harness 加载 → 系统提示组装
- Code Agent Runtime：skill-registry 评分选择 → 上下文注入 → 提示构建

- 版本化 Key-Value 存储
- 命名空间隔离（通常按 runId）

## 9. 制品与交接

### 9.1 制品类型

| 类型 | 说明 |
|---|---|
| `diff` | 代码变更差异 |
| `file` | 生成的文件 |
| `preview` | 预览链接 |
| `deploy` | 部署信息 |
| `log` | 执行日志 |
| `workflow` | 工作流定义 |

### 9.2 交接机制

- 上游 Agent 产出制品 → 存入 `.agenthub/handoff/{runId}/{taskId}/`
- Blackboard 记录 `artifact_ref` 条目
- 下游 Agent 从 `handoffPath` 读取，不依赖相对路径假设
- 消息元数据、workspace_tasks、Blackboard 三处存储制品引用

## 10. 冲突解决

### 10.1 检测

`ConflictResolver` 基于 filePath + diff 聚合，检测多 Agent 对同一文件的冲突修改。

### 10.2 解决策略

1. **自动合并**：尝试无冲突合并
2. **LLM 合并**：模型辅助合并
3. **人工解决**：展示冲突报告，用户选择 approve / reject / override

### 10.3 冲突报告

包含：冲突文件列表、每个文件的变体内容、合并结果、解决状态、用户操作记录。

## 16. 数据库设计

### 16.1 表结构总览

| 表名 | 记录数 | 说明 |
|---|---|---|
| `users` | 用户 | 账号、角色 |
| `sessions` | 会话 | direct/group + metadata.kind |
| `messages` | 消息 | 内容、类型、元数据 |
| `workspaces` | 工作区 | 名称、目标、路径 |
| `workspaceStates` | 工作区状态 | KV 存储 |
| `workspaceAgents` | Agent | 完整配置 |
| `workspaceAgentRelations` | Agent 关系 | 5 种关系类型 |
| `workspaceTasks` | 任务 | DAG、制品、状态 |
| `sessionMembers` | 成员 | 会话-用户/Agent |
| `orchestratorRuns` | 编排运行 | 计划、状态、冲突 |
| `orchestratorRunEvents` | 运行事件 | 事件流 |
| `taskClarifications` | 澄清问题 | 问题、选项、回答 |
| `orchestratorRunControls` | 运行控制 | 暂停/恢复/取消/重试 |
| `agents` | 全局 Agent | 供应商、配置 |
| `settings` | 设置 | KV 存储 |
| `blackboardEntries` | Blackboard | 命名空间、类型、版本 |
| `executionLogs` | 执行日志 | 类型、IO、耗时、Token |
| `tasks` | 遗留任务 | 旧版兼容 |

### 16.2 关键索引

- sessions: workspaceId + updatedAt
- messages: sessionId + createdAt
- workspaceTasks: runId + status
- orchestratorRunEvents: runId + createdAt
- blackboardEntries: namespace + key + schemaType
- executionLogs: runId + type + agentId
