## 2. 用户场景与用例

### 2.1 核心用户场景

#### 2.1.1 场景一：单 Agent 开发组件（"@Claude Code 写一个登录表单"）

小李是一名前端工程师，正在开发一个后台管理系统，需要一个带表单验证的登录页面。他打开
AgentHub，在左侧会话列表点击 "+" 新建对话，选择 Agent "Claude
Code"。在聊天输入框中，他输入："@Claude Code 帮我写一个 React
登录表单，包含邮箱和密码字段，使用 Tailwind CSS
样式，要有前端验证逻辑"，然后按 Enter 发送。

消息气泡立即出现在右侧（用户消息右对齐，主色调 #7B6D8D 背景）。约 1
秒后，Claude Code 头像左侧闪烁呼吸动画，状态文字显示 "正在思考..." [^1]
[^2]。随后，SSE
流式响应开始，代码块逐字出现在左侧消息气泡中------先是一个简洁的文字说明
"我来为你创建一个完整的登录表单组件"，紧接着是一个可折叠的代码块卡片，语法高亮显示
TypeScript/React 代码，右上角有 "复制" 和 "插入编辑器" 两个操作按钮。

代码块下方紧跟着一个网页预览卡片，iframe
沙箱中实时渲染出登录表单的实际效果
[^3]。预览卡片顶部有刷新按钮、设备尺寸切换器（Desktop/Tablet/Mobile）和全屏展开按钮。小李对配色不太满意，在输入框中追加一条消息："把按钮改成紫色渐变，添加一个记住我选项"。Claude
Code 理解上下文，返回修改后的代码 Diff
卡片------左侧显示旧代码，右侧显示新代码，新增行以绿色高亮，删除行以红色高亮
[^4]。小李点击 "一键应用" 按钮，Diff
被自动合并到当前代码中，预览卡片同步刷新。

整个交互过程约 30
秒，小李在聊天窗口中完成了一次完整的组件开发迭代，没有离开 AgentHub
界面，也没有在不同工具间切换上下文。

#### 2.1.2 场景二：多 Agent 协作开发全栈应用（"@Orchestrator 开发一个博客系统"）

产品经理小王有一个想法：做一个支持 Markdown 编辑的个人博客系统。他在
AgentHub 中打开与 Orchestrator 的对话，输入："@Orchestrator
我想开发一个个人博客系统，支持文章 CRUD、Markdown
编辑器、标签分类和响应式布局，请帮我安排开发"。

Orchestrator 收到消息后，在聊天流中展示一张任务拆解卡片------这是
AgentHub 最具标志性的交互设计之一。卡片标题为
"任务拆解计划"，下方展开一个子任务列表，每个子任务关联目标 Agent
的头像和名称：

- [ ] **前端页面开发** → \@Claude Code ---
  文章列表页、文章详情页、Markdown 编辑器组件
- [ ] **后端 API 开发** → \@Codex --- RESTful API
  设计（文章增删改查、标签管理）
- [ ] **数据库设计** → \@DBDesigner --- PostgreSQL
  Schema、表关系、索引设计

Orchestrator 卡片底部有一个 "确认执行"
按钮，小王点击后，三个子任务并行分发到对应的 Agent。聊天界面左侧出现一个
"执行进度" 悬浮面板，三个进度条分别显示各 Agent 的执行状态 [^5]
[^6]。@Claude Code 率先返回文章列表页的代码和预览，@DBDesigner
随后返回数据库 Schema 的 ERD 图（以图片消息展示），@Codex 最后返回 API
接口文档。

所有子任务完成后，Orchestrator 生成一张综合汇报卡片，汇总三个 Agent
的产出摘要，并标注潜在风险："API
路由与前端页面路由存在命名不一致，建议统一为 /api/posts 格式"。小王回复
"同意修改"，Orchestrator 自动协调 \@Codex 和 \@Claude Code
同步修正路由命名。最终产物以内联预览卡片形式展示------点击 "全屏预览"
后，一个完整的博客系统在 iframe 沙箱中运行，支持文章浏览和编辑 [^7]
[^8]。

#### 2.1.3 场景三：群聊式代码审查（"@CodeReviewer 审查这段代码 \@Tester 写测试用例"）

技术负责人老张在团队群聊中分享了一段用户认证的代码，希望获得审查和测试覆盖。他在群聊中发送："@CodeReviewer
请审查这段认证逻辑的代码 \@Tester
帮我写对应的单元测试用例"，并附带一个代码文件卡片。

AgentHub 的群聊交互机制在此场景中充分展现。@CodeReviewer
是一个专门负责代码审查的预设 Agent，内置了代码规范规则集（如 ESLint
规则、安全最佳实践）。它接收消息后，返回一张结构化的代码审查报告卡片，按严重程度分为三档：

- **严重**：密码使用 MD5 哈希，建议改用 bcrypt（附 OWASP 参考链接）
- **警告**：缺少输入参数校验，存在 SQL 注入风险
- **建议**：JWT token 过期时间 24 小时过长，建议缩短至 2 小时

每个审查项都可以展开查看详细说明和修复建议代码片段。

\@Tester meanwhile 开始分析代码逻辑，生成对应的 Jest
测试用例，以代码块形式返回。测试覆盖了正常登录、密码错误、用户不存在、SQL
注入尝试四种场景。老张在审查报告卡片上逐条操作------点击 "接受修复"
后，Orchestrator 自动将修复建议发送给 \@Claude Code 执行代码修改；点击
"忽略"
后该条目以删除线样式标记。所有审查意见处理完毕后，群聊中生成一份审查总结消息，记录本次审查的通过率和修改建议数量。

#### 2.1.4 场景四：一键部署上线（"部署到 Vercel" → 状态卡片 → 预览 URL）

前端开发者小陈完成了一个落地页的开发，准备部署上线。他在当前对话中直接发送："部署到
Vercel"，AgentHub 的意图识别系统识别到这是一个部署指令。

聊天界面中弹出一张部署配置面板卡片，预填充了当前项目名称（从对话上下文自动提取）和默认分支
main。小陈可以修改项目名、选择目标平台（Vercel/Netlify）、选择部署模式（静态站点/Serverless
Functions）。点击 "开始部署" 后，面板转换为部署状态卡片
[^9]------顶部显示平台图标（Vercel 三角形
Logo），中间是实时日志流区域（可折叠），底部是进度百分比条和预计剩余时间。

部署状态卡片经历三个视觉阶段："构建中"（蓝色进度条 +
旋转图标）、"部署中"（橙色进度条）、"部署成功"（绿色背景 +
对勾图标）。成功状态下，卡片展示预览 URL（如
https://agenthub-demo.vercel.app）、二维码分享按钮和一键复制链接按钮。小陈点击预览
URL，AgentHub
在新标签页打开部署后的网站，同时在聊天记录中保留部署历史------任何时候都可以回溯到某次部署的状态卡片查看对应版本。

部署失败时，状态卡片变为红色错误态，展示错误摘要（如 "构建失败：依赖
react-markdown 版本不兼容"）和 "查看完整日志"
展开按钮。小陈可以将错误信息直接转发给 \@Claude Code 请求修复。

### 2.2 用户旅程地图

#### 2.2.1 新用户 Onboarding 流程：注册 → 首次对话 → 了解 \@机制 → 完成第一次协作

\[图片占位符: 新用户 Onboarding
流程图，横向时间轴展示从注册到完成第一次协作的6个关键节点，标注每个节点的用户心理预期和系统设计目标\]

新用户的旅程设计遵循 "渐进披露" 原则
[^10]，不一次性暴露所有功能，而是引导用户在实践中自然学习核心机制。

**Step 1：注册与初始化（0-2 分钟）** 用户通过邮箱或 GitHub OAuth
注册，系统自动创建默认工作空间。初始化页面展示 AgentHub
的核心概念------"你的 AI 开发团队已就绪"------并预置 5 个常用 Agent
联系人：Claude Code（全栈开发）、Codex（后端
API）、CodeReviewer（代码审查）、Designer（UI/UX
设计）、Orchestrator（项目协调）。每个 Agent
配有头像、简短的能力描述和彩色标签。

**Step 2：首次对话引导（2-5 分钟）** 系统主动在对话列表中创建一条
"欢迎使用 AgentHub"
的系统消息，引导用户发送第一条消息。输入框下方有一排快捷指令按钮（"写一个
React
组件"、"审查我的代码"、"帮我设计数据库"），点击即可自动填充对应的消息文本和
\@Agent。这种 "模板触发" 设计降低了新用户的心理门槛------不需要记住每个
Agent 的名字和能力范围。

**Step 3：@机制发现（5-10 分钟）** 当用户在输入框中键入 "@" 字符时，弹出
Agent 选择器浮层------这是 \@机制的核心交互触点。浮层展示所有可用 Agent
的头像、名称和能力标签，支持键盘上下键选择和 Enter 确认 [^11]
[^12]。选择 \@Claude Code 后，Agent
名称在输入框中以彩色药丸标签形式展示，视觉上明确标示出消息的目标接收者。

**Step 4：第一次群聊协作（10-20 分钟）** 系统推荐新用户尝试一次简单的多
Agent 协作------"创建一个待办事项应用"。点击推荐卡片后，Orchestrator
自动拆解任务并协调两个 Agent
分别完成前端和后端开发。新用户通过这一次完整协作，理解了
\@触发、任务拆解、产物预览和 Diff 应用四个核心概念。

**Step 5：产物操作学习（20-30 分钟）** 用户在与 Agent
的交互中，自然接触到各种产物卡片------代码块的复制按钮、预览卡片的全屏展开、Diff
卡片的一键应用。每个操作按钮首次出现时带有微弱的脉冲动画提示，引导用户发现交互功能。

#### 2.2.2 高级用户 Workflow：自定义 Agent → 创建群聊模板 → 批量部署

\[图片占位符: 高级用户 Workflow 流程图，展示从自定义 Agent
到群聊模板再到批量部署的完整链路，标注每个环节的输入输出和系统反馈\]

当用户完成 Onboarding 并熟悉基础功能后，AgentHub
提供一系列高级能力支持复杂的开发工作流。

**自定义 Agent 创建** 高级用户经常需要针对特定技术栈或业务领域创建专用
Agent。AgentHub 提供三步向导式创建流程：基本信息（名称、头像、描述）→
System Prompt 编辑（提供模板库和语法高亮编辑器）→ 工具配置（选择该 Agent
可用的工具集，如文件操作、代码执行、API 调用）。创建完成后，新 Agent
立即出现在联系人列表和 \@选择器中，可以被任何会话调用。

**群聊模板** 对于重复性的协作模式（如 "前端开发 + 后端开发 + 代码审查"
的三人组），高级用户可以保存当前群聊配置为模板。模板保存了参与者 Agent
列表、每个 Agent
的角色描述和预设的协作规则。下次创建类似项目时，一键从模板创建群聊，省去逐个添加
Agent 的步骤。系统预置了 5 个常用模板：全栈应用开发、代码审查流程、Bug
修复协作、文档编写、数据管道构建 [^13]。

**批量部署** 对于需要同时部署到多个环境的场景（如开发环境 + 预发布环境 +
生产环境），高级用户可以选中多条部署历史记录，使用 "批量部署"
功能一次性触发。系统以矩阵卡片形式展示三个环境的部署进度，所有环境部署成功后生成一份综合部署报告，包含各环境的
URL、部署时间和版本号。

## 3. 功能模块设计

### 3.1 IM 聊天系统详细设计

#### 3.1.1 页面布局：左侧会话列表（20%）+ 中间聊天区域（60%）+ 右侧信息面板（20%）

AgentHub 的主界面采用经典的三栏布局，这一布局在
LobeChat、Slack、飞书等产品中经过充分验证 [^14] [^15]。左侧会话列表占比
20%（最小宽度 280px，最大宽度 360px），中间聊天区域占比
60%（弹性伸缩，最小宽度 600px），右侧信息面板占比 20%（最小宽度
260px，最大宽度 340px）。三栏之间以 1px 的 #e5e7eb 分割线分隔。

左侧会话列表顶部是搜索栏（高度 48px），支持按会话名称、Agent
名称或消息内容全文检索。搜索栏下方是 "+ 新建对话" 按钮（高度
40px，主色调背景，圆角
8px）。主体区域是会话列表，按最近活跃时间倒序排列，每个会话项高度
72px，展示头像（40×40px 圆角矩形）、会话名称（14px
加粗）、最后一条消息预览（12px 灰色，单行截断）、未读计数徽章（18px
圆形，红色背景白色数字）和最后活跃时间（12px
灰色）。右键菜单支持置顶、归档、删除、标记未读四项操作。

中间聊天区域顶部是会话标题栏（高度
56px），展示当前会话名称、参与者头像组（最多展示 3 个头像，超出显示 "+N"
徽标）和设置按钮。主体区域是消息列表，底部是输入区（最小高度
56px，最大高度 200px，支持多行文本和自适应增高）。消息列表使用 TanStack
Virtual 实现虚拟滚动 [^16] [^17]，当消息数量超过 50
条时自动启用，确保长会话的渲染性能不劣化。

右侧信息面板默认展示当前会话的参与者列表（每个 Agent
的详情卡片：头像、名称、角色标签、能力描述），点击下方 "查看详情" 可展开
Agent 的完整信息。面板顶部有标签切换器，可在
"参与者"、"产物"、"部署历史"三个标签间切换。

#### 3.1.2 会话列表设计：Agent 头像、最后消息预览、未读计数、在线状态、置顶/归档

会话列表是用户与 AgentHub
交互的最高频触点，其设计目标是在有限空间内传达最丰富的会话状态信息。

**Agent 头像系统**：每个 Agent
拥有唯一的头像图标（48×48px），采用渐变色背景 +
白色图标的设计语言。Claude Code 使用紫色渐变（#7B6D8D → #9B8EA8），Codex
使用蓝色渐变（#3b82f6 → #60a5fa），用户自建 Agent 使用灰色渐变（#6b7280
→ #9ca3af）。头像右下角有一个 10px
的状态指示圆点------绿色（在线/可响应）、橙色（思考中/流式输出中）、灰色（离线/不可用）[^18]
[^19]。

**消息预览与未读计数**：会话列表中每条会话展示最后一条消息的 40
字符预览。未读消息数量以红色圆形徽章（18px，白色 11px
加粗数字）叠加在头像右上角。当未读消息中包含 \@提及
用户的内容时，徽章变为橙色并显示 "@" 符号，以视觉优先级引导用户处理被
\@的消息 。

**置顶与归档**：用户可以将常用会话置顶，置顶会话固定在列表顶部，以微弱的底边框与下方普通会话分隔，头像旁显示一个置顶图钉图标。归档会话移入独立的
"已归档"
折叠区域，不再出现在主列表中，也不计入未读统计，但保留完整的聊天记录访问权限。

**排序规则**：会话列表默认按 lastActivityAt
时间戳倒序排列。置顶会话始终排在最前（内部按置顶时间倒序），普通会话按最后活跃时间倒序，归档会话不参与排序。

#### 3.1.3 聊天输入区：文本输入、@提及（下拉选择 Agent）、文件拖拽上传、快捷指令

聊天输入区是 AgentHub 最核心的交互组件之一，其设计直接影响用户与 Agent
协作的效率。

**文本输入框**：采用自适应高度的 textarea（最小 1 行，最大 10 行），支持
Shift+Enter 换行、Enter 直接发送。输入框背景为 #ffffff，边框为 1px
#e5e7eb，聚焦时边框过渡为 2px 主色调 #7B6D8D，过渡动画时长 200ms
。placeholder 文本根据当前会话上下文动态变化------单聊模式下显示 "给
\@Claude Code 发送消息..."，群聊模式下显示 "@Agent
开始协作..."，引导用户使用 \@机制。

**\@提及机制**：当用户键入 "@" 字符时，输入框下方弹出 Agent
选择器浮层（最大高度 280px，圆角 12px，阴影 0 4px 20px
rgba(0,0,0,0.08)）。浮层展示所有可用 Agent
的列表，每个选项包含头像（28×28px）、名称（13px 加粗）、能力标签（11px
灰色胶囊标签）和状态指示点 。用户可通过上下方向键选择（选中项以 #f3f4f6
背景高亮），Enter 确认，Esc 关闭。选中后，Agent
名称以彩色药丸标签形式插入输入框中（背景色为该 Agent 的标识色，文字白色
13px，圆角 16px，内边距 2px 10px），标签两侧可继续输入普通文本。

**文件拖拽上传**：输入框上方有一个可折叠的文件附件区域。用户可以直接拖拽文件到输入框区域，系统检测拖放事件后高亮输入框边框（2px
虚线
#7B6D8D），释放后自动上传。上传过程中显示进度条（蓝色线性进度），上传完成后以文件卡片形式附着在输入框上方，展示文件名、大小和删除按钮。支持的最大文件大小为
10MB，支持的格式包括代码文件（.js/.ts/.jsx/.tsx/.py/.go
等）、图片（.png/.jpg/.gif）、文档（.md/.pdf/.txt）。

**快捷指令**：输入框右侧有一排快捷操作按钮（24×24px 图标按钮，灰色
#9ca3af，hover 变深
#4b5563）：代码片段插入按钮（\</\>）、表情选择按钮、上传文件按钮。输入框左侧有一个快捷指令菜单按钮，点击后弹出预设指令模板列表（如
"/code 写代码"、"/review 审查代码"、"/deploy
部署"），选择后自动填充对应的消息文本。

#### 3.1.4 消息气泡设计：用户消息（右对齐，主色调）、Agent 消息（左对齐，区分颜色）、系统消息（居中，弱化）

消息气泡是聊天界面的视觉核心，三种消息类型在布局、色彩和交互上有明确区分。

**用户消息**：右对齐，最大宽度 70%。气泡背景使用主色调 #7B6D8D，文字白色
#ffffff，圆角设置为 12px 左上、12px 左下、4px 右下、12px
右上（右下小圆角形成指向发送者的视觉"尾巴"）。字号 14px，行高
1.6，内边距 12px
16px。消息气泡下方显示发送时间戳（11px，#9ca3af，右对齐）。如果消息包含
\@提及，被 \@的 Agent 名称在气泡中以白色下划线高亮。

**Agent 消息**：左对齐，最大宽度 75%。每个 Agent 的消息气泡左侧展示
Agent 头像（32×32px），头像与气泡间距 8px。气泡背景为 #ffffff，边框 1px
#e5e7eb，阴影 0 1px 3px rgba(0,0,0,0.04)，圆角设置为 4px 左上、12px
右上、12px 右下、12px 左下（左上小圆角形成"尾巴"）。Agent 名称以 12px
加粗显示在气泡上方（颜色为该 Agent 的标识色），消息内容区域 14px
#1f2937。

**系统消息**：居中对齐，最大宽度
80%。不使用气泡样式，而是以弱化文字展示------12px #9ca3af，上下有 16px
间距，内容前以 "·" 符号分隔（如 "· Orchestrator 创建了 3 个子任务
·"）。系统消息包括：会话创建通知、Agent
加入/离开通知、任务拆解通知、部署状态变更通知。

**消息状态指示**：用户消息气泡右下角显示状态图标------空心对勾（发送中）、实心对勾（已送达）、双实心对勾（对方已读）。Agent
消息气泡左下角显示 "编辑中" 的呼吸动画点（三个渐变圆点依次放大缩小，间隔
400ms），当 Agent 流式输出完成时动画停止。

#### 3.1.5 消息类型渲染：文本（Markdown）、代码块（语法高亮+复制按钮）、文件卡片、网页预览卡片

AgentHub 支持丰富的消息内容类型，每种类型都有专门的渲染组件。

**文本消息**：使用 react-markdown 渲染 Markdown 内容 [^20]，支持 GitHub
Flavored Markdown（表格、任务列表、删除线等）。代码内联以 `code`
标签展示，背景 #f3f4f6，圆角 4px，内边距 2px
4px。链接自动解析为可点击的超链接（颜色 #7B6D8D，hover 下划线）。

**代码块**：AI
消息中最常见的内容类型。代码块以卡片形式展示，顶部有语言标识标签（如
"typescript"，11px 灰色胶囊标签，背景
#f3f4f6）、"复制"按钮（点击后图标变为对勾，2 秒后恢复）和 "插入编辑器"
按钮。代码区域使用 Shiki 语法高亮 [^21]（VS Code 同款 TextMate
引擎，支持 100+ 语言和多种主题），字体 JetBrains Mono 13px，行高
1.5，行号以灰色显示在左侧。代码块最大高度 400px，超出时显示滚动条。

**文件卡片**：上传的文件以卡片形式展示（宽度 100%，最大宽度 400px，高度
64px，圆角 8px，边框 1px
#e5e7eb）。左侧是文件类型图标（根据扩展名显示不同颜色和图标），中间是文件名（14px
加粗，单行截断）和文件大小（12px
灰色），右侧是下载按钮。图片文件在聊天中直接展示（最大宽度 480px，圆角
8px，懒加载）。

**网页预览卡片**：Agent 生成的网页/HTML 产物以内联 iframe
预览卡片展示。卡片顶部有标题栏（产物名称 + 操作按钮组），主体区域是
iframe 沙箱（默认高度 320px，宽度 100%） [^22]。iframe 使用
sandbox="allow-scripts allow-same-origin" 安全策略，通过 postMessage
与父窗口通信实现代码热更新。预览卡片支持三种设备尺寸切换（Desktop
100%/Tablet 768px/Mobile 375px），切换时预览区域宽度平滑过渡（300ms
ease-out）。点击全屏按钮后，预览以模态框形式展开（占据 90% 视口，圆角
12px，背景遮罩 rgba(0,0,0,0.6)），Esc 键关闭。

#### 3.1.6 群聊交互：@Agent 触发、Agent 排队等待指示器、Orchestrator 任务拆解展示

群聊是 AgentHub 的核心差异化功能，其交互设计需要解决多 Agent
并发时的视觉混乱问题。

**\@Agent 触发**：在群聊中，用户输入 "@Agent名称" 后发送消息，被 \@的
Agent 会自动响应。消息气泡中 \@提及的 Agent
名称以彩色药丸标签展示（颜色为该 Agent
的标识色），视觉上与普通文本清晰区分。被 \@的 Agent
头像在消息发送后短暂弹跳（scale 1.0 → 1.2 →
1.0，300ms），作为被唤醒的视觉反馈。

**Agent 排队等待指示器**：当多个 Agent 同时被 \@或 Orchestrator
分派多个子任务时，聊天区域顶部显示一个水平排列的 Agent 队列指示条。每个
Agent
以圆形头像（28×28px）展示，头像外环有三种状态：旋转的进度环（执行中，主色调描边）、静态绿色圆点（已完成）、静态灰色圆点（等待中）。指示条下方有一条细进度线，显示整体完成百分比。用户点击某个
Agent 的头像，消息列表自动滚动到该 Agent 的最新消息位置。

**Orchestrator 任务拆解展示**：当用户 \@Orchestrator
并请求复杂任务时，Orchestrator 在聊天流中生成一张 "任务拆解"
卡片。卡片采用折叠面板设计（Accordion），默认展开。顶部是任务总述（如
"博客系统开发 --- 3
个子任务"），下方是每个子任务的条目------左侧复选框（未开始为空框、进行中为旋转图标、已完成为绿色对勾），中间是任务描述，右侧是负责
Agent
的头像和名称。每个子任务条目可点击展开，展开后显示该子任务的详细描述、预期产物和预估耗时。卡片底部有一个
"查看执行进度" 按钮，点击后右侧信息面板切换到 "执行进度" 标签，展示各
Agent 的实时状态。

群聊消息的顺序遵循 "先来先服务 + Orchestrator 优先级" 规则：Orchestrator
的系统消息（任务派发、进度更新、结果汇总）优先级最高，插入到最新消息位置；各
Agent 的回复按完成时间顺序排列。用户可以通过右键菜单中的 "重新生成"
选项要求某个 Agent 重新执行其任务。

### 3.2 Orchestrator 协调器设计

#### 3.2.1 任务拆解展示：用户消息下方展开子任务列表，每个子任务关联目标 Agent

Orchestrator
的核心价值在于将用户的模糊意图转化为结构化的执行计划。当用户发送一个复杂请求（如
"帮我开发一个电商网站"）后，Orchestrator 首先展示 "正在分析需求..."
的思考状态（头像呼吸动画 + 渐变文字），约 3-5 秒后生成任务拆解卡片。

任务拆解卡片采用纵向时间轴布局，左侧是一条 2px
宽的主色调竖线，右侧是子任务节点。每个节点包含：子任务序号（圆形徽章，24×24px，主色调背景白色数字）、子任务标题（14px
加粗）、子任务描述（13px #6b7280，最多 2 行）、负责 Agent 的头像 +
名称（12px）、预估耗时标签（11px 灰色胶囊）。节点之间有 24px
间距，连接线以虚线形式呈现。

子任务列表下方有两个操作按钮："确认执行"（主色调按钮，点击后
Orchestrator 开始分派任务）和
"调整任务"（次要按钮，点击后弹出编辑面板，用户可以增删子任务或修改任务描述）。用户确认后，每个子任务节点左侧的序号变为进度指示器，按执行状态动态更新。

任务拆解卡片的消息类型为 system +
orchestrator_plan，存储在消息数据库中，支持历史回溯和重新触发。

#### 3.2.2 执行进度可视化：进度条或步骤指示器，显示各 Agent 执行状态

执行进度可视化是让用户感知多 Agent 协作过程的关键设计。AgentHub
提供两种进度展示模式。

**紧凑型 ---
聊天内进度条**：在每个子任务消息气泡的顶部，嵌入一个细进度条（高度
3px，圆角
2px）。未开始的任务不显示进度条，进行中的任务显示蓝色流动动画（background
linear-gradient 以 1s
周期水平移动），已完成的任务显示绿色实心条。进度条右侧显示百分比数字（11px，#6b7280）。

**展开型 --- 右侧信息面板**：用户点击 "查看完整进度" 后，右侧面板切换到
"执行进度" 标签。该视图采用看板（Kanban）布局，三列分别对应
"待执行"、"进行中"、"已完成"。每个任务以卡片形式展示（宽度 100%，圆角
8px，边框 1px），包含任务标题、负责 Agent
头像、耗时计时器（进行中任务显示已过时间）和状态图标。用户可以将任务卡片在不同列间拖拽以调整执行顺序（需要
Orchestrator 确认）。

**Agent 状态实时同步**：各 Agent 的执行状态通过 WebSocket 实时推送到前端
[^23] [^24]。状态机定义为：idle（空闲）→ assigned（已分配）→
executing（执行中，显示思考动画）→ streaming（流式输出中）→
completed（已完成）→
failed（失败，显示红色错误图标）。失败的任务可以点击 "重试"
按钮重新执行，或点击 "换 Agent 执行" 将任务分配给其他 Agent。

#### 3.2.3 结果聚合展示：Orchestrator 综合汇报卡片，整合各 Agent 产出摘要

当所有子任务完成后，Orchestrator 生成一张综合汇报卡片，这是多 Agent
协作的"收官之作"。

汇报卡片采用报告式布局，顶部是标题（"任务完成 --- 博客系统开发"，16px
加粗，主色调）和完成时间戳。主体区域分为三个部分：

**摘要区**：一句话总结本次协作的产出（"已成功创建博客系统的前端页面、后端
API 和数据库 Schema"），下方是各 Agent 的贡献统计------每个 Agent
以横向条形图展示工作量占比（条长度按代码行数/处理时间比例计算）。

**产出列表区**：按 Agent
分组展示各子任务的产出物。每个产出项包含类型图标（代码文件、网页预览、API
文档、数据库图）、产出名称、简要描述和 "查看详情"
链接。点击后消息列表滚动到该产出的原始消息位置。

**风险提示区**：如果 Orchestrator 检测到潜在问题（如 API
路由命名不一致、缺少错误处理、依赖版本冲突），以黄色警告卡片形式列出，每条风险附带
"建议修复" 按钮。点击后 Orchestrator 自动创建修复子任务并分配给对应
Agent。

汇报卡片底部有一个 "全部确认" 按钮和一个 "继续优化" 按钮。"全部确认"
将所有产出标记为最终版本，解锁部署功能；"继续优化"
允许用户针对特定产出提出修改意见，触发新一轮协作。

#### 3.2.4 人机协作节点：需要用户确认时展示审批卡片（Approve/Reject/Modify）

并非所有任务都应该自动执行------涉及架构决策、资源消耗大或风险较高的操作需要用户审批。这种人机协作（Human-in-the-loop）节点是确保
AI 不越界的关键设计 。

审批卡片以醒目的视觉形式插入聊天流------左侧有一条 4px
宽的橙色竖线，背景为 #fef3c7（浅黄色），圆角
8px。卡片顶部显示审批类型标签（"需要你的确认"，11px
橙色胶囊标签），主体是审批内容描述（如 "Claude Code 建议将数据库从
SQLite 切换为 PostgreSQL 以支持并发访问，预计增加 2
分钟配置时间，是否同意？"），底部是三个操作按钮："同意"（绿色
#22c55e，主按钮样式）、"拒绝"（红色
#ef4444，次要按钮样式）、"修改后同意"（灰色，点击后弹出文本输入框让用户补充条件）。

审批卡片的状态会实时更新：待处理（橙色边框）、已批准（绿色边框 +
对勾图标）、已拒绝（红色边框 + 叉号图标）、已修改（蓝色边框 +
编辑图标）。用户的审批决策会作为新的上下文消息发送给
Orchestrator，影响后续的任务编排逻辑。

### 3.3 Agent 管理系统设计

#### 3.3.1 Agent 联系人列表：网格卡片布局，展示头像、名称、描述、能力标签、状态

Agent 联系人列表是用户发现和管理 Agent 的中心入口，通过左侧边栏的
"Agent" 图标进入。

页面采用响应式网格布局，每行 3-4 个 Agent 卡片（卡片宽度自适应，最小
240px）。每个卡片包含：Agent 头像（64×64px，圆角 16px，渐变背景）、Agent
名称（16px 加粗）、Agent 描述（13px #6b7280，最多 2
行）、能力标签组（最多 3 个标签，11px
胶囊标签，每个标签有独立的颜色编码------前端开发=蓝色、后端开发=绿色、代码审查=橙色、UI
设计=紫色）、在线状态指示点（8px 圆点，绿色/橙色/灰色）和 "开始对话"
按钮（主色调小号按钮）。

卡片 hover 效果：阴影从 0 1px 3px rgba(0,0,0,0.04) 增强为 0 8px 24px
rgba(0,0,0,0.08)，卡片整体上移 2px（transform:
translateY(-2px)），过渡时长 200ms ease-out。

页面顶部有搜索框（支持按名称和能力标签筛选）和分类筛选器（"全部"、"内置
Agent"、"我的 Agent"、"已安装"）。

#### 3.3.2 Agent 详情面板：能力描述、System Prompt 预览、工具集列表、使用统计

点击 Agent 卡片后，右侧滑出一个详情面板（宽度 400px，从右侧滑入动画
300ms ease-out，背景遮罩 rgba(0,0,0,0.3)）。

面板分为四个区域：

**基本信息区**：Agent
头像（80×80px）、名称、描述、创建者信息（内置/用户创建/社区分享）、创建时间和使用次数统计。

**能力描述区**：Agent 的核心能力列表，每项能力以图标 + 标题 +
描述的纵向列表形式展示。例如 Claude Code 的能力包括：React/TypeScript
代码生成、组件调试、样式优化、测试用例编写。

**System Prompt 预览区**：System Prompt 是决定 Agent 行为的核心配置
[^25]。面板以只读代码块形式展示 System Prompt 的前 10 行，点击 "展开完整
Prompt" 后显示全部内容。用户如果是该 Agent 的创建者，可以点击 "编辑"
按钮进入编辑模式（使用 Monaco Editor，支持语法高亮和自动保存）。

**工具集列表区**：展示该 Agent
可调用的工具集，每个工具以展开面板形式展示------工具名称、功能描述、调用参数列表和权限级别（只读/读写/管理员）。工具集包括：文件操作（读/写/删除）、代码执行（沙箱内运行）、API
调用（HTTP 请求）、数据库查询、搜索（Web 搜索/代码搜索）。

**使用统计区**：近 30 天的使用趋势图（小型折线图，高度
80px），标注总调用次数、平均响应时间和成功率百分比。

#### 3.3.3 自建 Agent 向导：三步流程（基本信息 → System Prompt → 工具配置 → 测试）

自建 Agent 是 AgentHub
支持用户扩展平台能力的重要功能。创建流程采用向导式（Wizard）设计，顶部显示进度指示器（三步，当前步骤高亮，已完成步骤显示对勾），底部有
"上一步" 和 "下一步" 按钮。

**Step 1 --- 基本信息**：表单包含 Agent 名称（必填，2-30
字符，支持中英文）、头像选择（预设 12 个渐变色图标 +
自定义上传）、简短描述（必填，一句话描述 Agent
的用途）和详细说明（可选，支持 Markdown）。表单右侧实时预览卡片效果。

**Step 2 --- System Prompt 编辑**：使用 Monaco Editor（懒加载）编辑
System Prompt。编辑器左侧提供一个模板库侧边栏，预设 8
个常用模板（全栈开发助手、代码审查专家、测试工程师、UI
设计师、数据库架构师、DevOps
工程师、技术文档编写、产品经理）。选择模板后自动填充 Prompt
内容，用户可以在此基础上修改。编辑器支持语法高亮、自动补全和实时字数统计。

**Step 3 --- 工具配置**：以开关 +
配置面板的形式展示可用工具集列表。每个工具有一个启用开关（Toggle），启用后展开配置面板。例如
"代码执行"
工具可以配置：允许的语言（JavaScript/TypeScript/Python/Go）、执行超时时间（默认
30s）、内存限制（默认 128MB）和网络访问权限（允许/禁止）。

**Step 4 --- 测试**：向导的最后一步是测试环节。用户输入一条测试消息（如
"你好，请介绍一下你自己"），系统调用该 Agent
并展示响应结果。用户可以在此轮迭代调整 Prompt
和工具配置，直到获得满意的响应质量。测试通过后点击 "创建 Agent"
完成向导，新 Agent 立即出现在联系人列表中。

#### 3.3.4 Agent 市场（P2）：分类浏览、搜索筛选、一键安装、评分评价

Agent 市场是 AgentHub 的 P2 功能，用于社区 Agent 的分享和发现 。

市场首页采用分类导航 +
瀑布流布局。顶部是分类标签栏（"全部"、"前端开发"、"后端开发"、"DevOps"、"数据科学"、"测试"、"文档"、"设计"），主体是
Agent
卡片网格（与联系人列表卡片样式一致，但额外展示评分星标和下载次数）。

每个市场 Agent 卡片展示：评分（1-5
星，黄色星标）、下载次数、作者头像和名称、最近更新时间。点击卡片进入详情页，展示完整的
Agent 介绍、能力说明、用户评价列表和 "安装到我的工作空间"
按钮。安装过程一键完成，Agent 立即出现在用户的联系人列表中。

搜索功能支持按名称、标签、作者搜索，支持排序（最热门、最高评分、最新发布）。筛选器支持按工具集类型、适用语言、权限需求等维度过滤。

### 3.4 产物系统设计

#### 3.4.1 网页预览卡片：iframe 沙箱预览、刷新按钮、全屏展开、设备尺寸切换

产物预览是 AgentHub 展示 AI 生成成果的核心方式。网页预览卡片设计遵循
"即时可见、安全隔离、交互丰富" 的原则 。

**卡片结构**：顶部标题栏（高度 36px，背景 #f9fafb，圆角顶部
12px）左侧展示产物类型图标（地球图标表示网页）和产物名称，右侧是操作按钮组（刷新按钮、设备尺寸切换器
Desktop/Tablet/Mobile、全屏展开按钮、更多操作菜单）。主体区域是 iframe
沙箱（默认高度 320px，最小高度 200px），底部是状态栏（高度 28px，展示
iframe 加载状态和 URL）。

**iframe 沙箱安全**：所有预览均使用
`<iframe sandbox="allow-scripts allow-same-origin allow-popups">` 配置
。对于 AI 生成的不可信代码，额外限制 `allow-forms` 和
`allow-top-navigation`。父窗口通过 `postMessage` API 与 iframe
通信，实现代码推送和热更新。CSP 头设置为
`Content-Security-Policy: frame-ancestors 'self';` 防止点击劫持 。

**设备尺寸切换**：三种预设尺寸------Desktop（100% 宽度）、Tablet（768px
居中）、Mobile（375px 居中）。切换时 iframe 宽度使用 CSS
transition（width 300ms cubic-bezier(0.4, 0, 0.2,
1)）平滑过渡，模拟真实设备的边框装饰（Tablet 显示圆角边框和 home
指示条，Mobile 显示刘海屏和 home 横条）。

**全屏展开**：点击全屏按钮后，预览以模态框形式展开。模态框占据 90vw ×
90vh，圆角 12px，背景遮罩 rgba(0,0,0,0.6) 带毛玻璃效果（backdrop-filter:
blur(4px)）。全屏模式下设备尺寸切换器移动到顶部中央，底部增加 URL
输入框（允许用户手动导航）。Esc 键或点击遮罩关闭全屏。

**Sandpack 集成（可选增强）**：对于 React/Vite 项目，可选择使用 Sandpack
替代简单 iframe 。Sandpack 提供热模块重载（HMR）、npm
依赖安装、错误边界捕获等高级功能。启用 Sandpack 的预览卡片顶部会显示
"Powered by Sandpack" 标签，错误时展示红色错误遮罩和堆栈追踪。

#### 3.4.2 代码 Diff 卡片：分栏对比（左旧右新）、行级高亮（增绿删红）、一键应用按钮

Diff 视图是开发者评审 AI 代码修改的核心工具。AgentHub 的 Diff
卡片设计参考 GitHub Pull Request 的 diff 界面 。

**卡片结构**：顶部是文件信息栏------左侧展示文件名（14px
加粗）和文件路径（12px 灰色），右侧是变更统计（"+45
-12"，绿色和红色数字）和操作按钮组（"一键应用"、"复制
Diff"、"展开/折叠"）。

**Diff 视图区域**：默认使用左右分栏对比（split
view），左侧展示旧代码（灰色背景
#f9fafb），右侧展示新代码（白色背景）。变更行以背景色高亮------新增行背景
#dcfce7（浅绿）、删除行背景
#fee2e2（浅红）、修改行同时展示左右两侧对比。每行左侧有行号（12px
灰色，等宽字体）。

用户可以切换到内联视图（inline
view），此时删除行和新增行在同一面板中上下排列。视图切换按钮在文件信息栏右侧。

**一键应用**：点击 "一键应用" 按钮后，系统使用 `diff` npm 包的
`applyPatch` 函数 [^26]将修改应用到当前项目文件。应用成功后在 Diff
卡片上方显示绿色成功提示（"已成功应用到 src/components/Login.tsx"，3
秒后自动消失），并自动刷新网页预览卡片。应用失败时显示红色错误提示和
"查看错误详情" 链接（通常是上下文不匹配导致，可切换到手动编辑模式）。

**代码高亮**：Diff 中的代码使用 Shiki 语法高亮
，与代码块消息保持一致的高亮质量和主题风格。

#### 3.4.3 部署状态卡片：平台图标、部署进度动画、成功/失败状态、访问链接

部署状态卡片将部署过程可视化为聊天流中的一个"活"的实体，用户可以实时观察部署进展。

**卡片结构**：顶部是平台标识区------左侧是目标平台图标（Vercel
三角形/Netlify 三角箭，32×32px），中间是平台名称和项目名（14px
加粗），右侧是状态标签（"构建中"/"部署中"/"部署成功"/"部署失败"，胶囊标签，对应颜色为蓝/橙/绿/红）。

**进度区域**：构建阶段展示一个分段进度条------"构建 → 部署 →
完成"三个阶段，当前阶段高亮，已完成阶段显示对勾，未到达阶段灰色。进度条下方是实时日志流区域（默认折叠，点击
"查看日志" 展开），日志以等宽字体 12px
展示，最新日志行自动滚动到可视区域。

**成功状态**：部署成功后，卡片背景过渡为浅绿色
(#f0fdf4)，顶部状态标签变为 "部署成功"（绿色胶囊）。主体区域展示预览
URL（如 https://my-app.vercel.app，蓝色可点击链接，14px
加粗）、二维码（100×100px，点击放大）和操作按钮组（"打开网站"、"复制链接"、"分享"）。

**失败状态**：部署失败后，卡片背景过渡为浅红色 (#fef2f2)，状态标签变为
"部署失败"（红色胶囊）。主体区域展示错误摘要（如
"依赖安装失败：react-markdown@9.0.0 与 next@14.0.0 不兼容"）和
"查看完整日志" 展开按钮。底部有 "重试部署" 和 "发送给 Agent 修复"
两个操作按钮------点击后者将错误信息自动打包为一条 \@Claude Code
的消息。

#### 3.4.4 产物历史：时间轴展示版本快照、对比任意两个版本、回滚操作

产物历史功能让用户回溯 AI 产出的演进过程，支持版本对比和回滚。

**时间轴视图**：右侧信息面板的 "产物"
标签下，以纵向时间轴形式展示该会话的所有产物版本。时间轴左侧是版本节点（圆形，16px，主色调边框），节点间以
2px 虚线连接。每个版本条目包含：版本号（"v3"，12px
加粗）、生成时间（相对时间，如 "2 小时前"）、生成者（Agent 头像 +
名称）、变更摘要（"修改了按钮样式和表单验证逻辑"，13px）和操作按钮（"预览"、"对比"、"回滚"）。

**版本对比**：勾选两个版本后，点击 "对比" 按钮打开对比视图。对比视图使用
Monaco DiffEditor
[^27]展示两个版本的完整差异，支持语法高亮、行内差异标记和变更导航。Diff
视图的交互与 3.4.2 中描述的 Diff 卡片一致。

**回滚操作**：点击 "回滚" 按钮后弹出确认对话框（"确定要回滚到 v2
吗？当前版本 v3
将被替换"），确认后将选中版本的内容恢复为当前版本，并在聊天流中生成一条系统消息记录回滚操作。回滚后的产物自动刷新预览卡片。

版本存储采用 "完整快照 + Diff 链" 混合策略 ：最近 10
个版本存储完整快照，超过 10 个版本的历史版本仅保留与上一版本的
Diff，需要回溯时逐层应用 Diff 链还原。

### 3.5 部署流程设计

#### 3.5.1 部署触发：聊天中识别"部署"关键词，弹出部署配置面板

部署流程的入口设计追求极简------用户在任意对话中发送包含
"部署"、"deploy"、"发布"、"上线" 等关键词的消息，AgentHub
的意图识别系统即触发部署流程。

部署配置面板以模态卡片形式弹出（宽度 480px，圆角 16px，阴影 0 20px 60px
rgba(0,0,0,0.15)）。面板顶部是标题 "部署配置"，主体区域包含以下配置项：

- **目标平台**：平台选择卡片组（Vercel --- 黑色卡片带三角 Logo、Netlify
  --- 绿色卡片带三角箭 Logo），单选，选中项以 2px 主色调边框高亮。
- **项目名称**：文本输入框，预填充当前会话名称的 kebab-case 格式（如
  "blog-system"），用户可修改。项目名称下方有实时可用性检查（"该名称在
  Vercel 上可用" 绿色提示 / "已被占用" 红色提示）。
- **分支选择**：下拉选择器，默认 main，支持自定义分支名。
- **部署模式**：单选按钮组------"静态站点"（默认，适用于纯前端项目）和
  "Serverless"（适用于全栈项目，需额外配置环境变量）。

面板底部是 "开始部署" 主按钮和 "取消"
文本按钮。所有配置项均有默认值，用户可以直接点击 "开始部署" 一键完成。

#### 3.5.2 部署配置：选择目标平台（Vercel/Netlify）、填写项目名、选择分支

部署配置的设计遵循 "智能默认 + 可选高级"
的原则。基础配置（平台、项目名、分支）足以满足 80%
的部署场景，高级配置按需展开。

**高级配置折叠面板**：点击 "高级配置"
后展开额外选项------环境变量编辑（键值对表格，支持从 .env
文件导入）、构建命令覆盖（默认 "next build"，可修改）、输出目录（默认
"dist"）、Node.js 版本选择（18/20/22）。

**平台特定配置**：选择 Vercel 时显示 "Vercel Team"
选择器（个人/团队）；选择 Netlify 时显示 "自定义域名" 输入框。

配置面板使用表单验证------项目名必填、只能包含小写字母/数字/连字符、不能以连字符开头或结尾。验证错误以红色文字显示在对应字段下方。

#### 3.5.3 部署中状态：实时日志流、进度百分比、预计剩余时间

部署过程中，部署状态卡片在聊天流中实时更新。进度数据通过 SSE 流式推送
[^28]，前端使用 Zustand 状态管理实时响应更新 [^29] [^30]。

**实时日志流**：日志区域以终端风格展示（黑色背景 #1a1a2e，绿色等宽字体
12px，内边距 12px，圆角
8px）。新日志行从底部追加，自动滚动保持最新行可见。日志行有类型区分------info（白色）、warning（黄色）、error（红色）、success（绿色）。日志区域右上角有
"复制全部日志" 和 "下载日志" 按钮。

**进度计算**：前端根据已完成的构建步骤计算整体进度。以 Next.js
项目为例------"安装依赖"（0-30%）→ "编译代码"（30-70%）→
"优化输出"（70-90%）→ "上传到
CDN"（90-100%）。每个阶段的耗时基于历史数据预估，显示 "预计剩余 45 秒"
的文字提示。

**取消部署**：部署进行中时，"取消部署"
按钮可用。点击后发送取消信号到部署服务，已上传的资源自动清理。

#### 3.5.4 部署成功：预览 URL 卡片、二维码分享、一键复制链接

部署成功后的交互设计强调即时分享和快速验证。

**预览 URL 卡片**：部署状态卡片转换为成功态后，主体区域展示： -
网站缩略图（使用 html2canvas 或类似库生成的 480×270px 截图，圆角
8px，点击放大） - 网站标题（从 HTML `<title>` 标签提取） - 完整
URL（蓝色链接，点击在新标签页打开） - 二维码（120×120px，使用 qrcode.js
生成，鼠标悬停显示 "用微信扫描预览" 提示） -
操作按钮组："打开网站"（主按钮）、"复制链接"（次按钮，点击后图标变对勾）、"分享到
Twitter"（图标按钮）

**部署历史**：每次部署记录保存在右侧信息面板的 "部署历史"
标签中，按时间倒序排列。每条记录包含：部署时间、版本号、目标平台、项目名、状态（成功/失败）、URL

**连续部署**：在同一个对话中进行多次部署时，新的部署状态卡片自动覆盖旧卡片（旧卡片折叠为精简模式，显示

## 4. 交互设计规范

### 4.1 全局交互原则

#### 4.1.1 即时反馈：所有操作在 200ms 内有视觉响应

AgentHub 的交互设计遵循 "200ms 反馈法则"------任何用户操作必须在 200
毫秒内产生可感知的视觉响应，让用户确信系统已接收指令并正在处理
。这一原则贯穿于产品的每一个交互触点。

**按钮点击反馈**：所有可点击元素（按钮、图标按钮、列表项）在 mousedown
事件中立即响应------按钮缩放至 0.96（transform:
scale(0.96)），背景色加深 5%，过渡时长 80ms ease-out。mouseup 后 120ms
内恢复原状。这种微小的缩放动画模拟了物理世界的"按下"触感，比单纯的 hover
变色更具操作确认感。

**加载状态反馈**：异步操作（发送消息、调用 Agent、部署触发）在 200ms
内展示加载指示。发送消息的按钮在点击后 100ms 内转换为旋转加载图标（16px
旋转器，主色调 #7B6D8D，1s linear infinite 旋转）。如果操作在 300ms
内完成，不显示额外加载状态；如果超过
300ms，在相关区域展示骨架屏（shimmer 动画，背景 linear-gradient 以 1.5s
周期水平流动）。

**网络延迟兜底**：当网络延迟超过 1 秒时，在操作区域展示
"网络较慢，请稍候..." 的文本提示（12px 灰色，带呼吸动画）。超过 5
秒时提供 "取消操作" 按钮，让用户可以主动中断。

#### 4.1.2 渐进披露：复杂功能分层展示，不一次性暴露所有选项

渐进披露（Progressive Disclosure）是 AgentHub 处理功能复杂性的核心策略
。产品在三个层次上实施渐进披露：

**初级层 ---
默认可见**：聊天输入框、发送按钮、基础消息操作（复制、重新生成）。这是新用户首次接触到的界面，只展示最高频、最低学习成本的交互。

**中级层 ---
上下文触发**：当用户与系统产生特定交互时，相关高级功能自动浮现。例如：用户在输入框中键入
"@" 时弹出 Agent 选择器；用户选中代码块时浮现 "在聊天中修改"
的浮动按钮；用户鼠标悬停在消息气泡上时显示操作工具栏（回复、引用、删除）。

**高级层 ---
主动探索**：通过快捷键、右键菜单和设置面板访问高级功能。例如：Cmd/Ctrl+Shift+P
打开命令面板（Command
Palette），提供所有功能的模糊搜索入口；右键菜单提供 "Fork
会话"、"导出聊天记录"、"创建群聊模板"
等功能。这些功能不在界面上占据任何固定空间，但随时可供有经验的用户调用。

**产物卡片的分层交互**：产物预览卡片默认以紧凑型展示（标题 + 预览 +
基本操作），点击 "展开"
后进入展开型（增加设备切换、全屏、设置面板），需要编辑时点击 "编辑"
进入完整编辑器模式。每一层的过渡都使用平滑动画（height/width 300ms
cubic-bezier(0.4, 0, 0.2, 1)），让用户感知到层次的递进关系。

#### 4.1.3 智能默认：常见操作一键完成，高级选项可展开

智能默认（Smart
Defaults）减少用户的决策负担，让高频操作零配置完成，低频操作按需定制。

**部署智能默认**：用户在聊天中发送 "部署"
后，部署配置面板已预填充所有字段------目标平台默认为
Vercel（如果项目使用 Next.js）或
Netlify（如果项目使用静态站点），项目名称从会话名称自动生成 kebab-case
格式，分支默认为 main。80% 的场景下用户只需点击 "开始部署"
即可完成全部操作。

**Agent 选择智能默认**：Orchestrator
在任务拆解时，根据子任务类型自动推荐最合适的
Agent------前端开发任务默认分配给 Claude Code，后端 API 任务默认分配给
Codex，数据库设计任务默认分配给
DBDesigner。用户可以接受默认分配，也可以手动调整。

**消息输入智能默认**：群聊中如果用户未 \@任何 Agent
直接发送消息，系统根据消息内容自动路由------包含 "代码"、"组件"、"页面"
等关键词的消息路由给 Claude Code；包含 "API"、"接口"、"后端"
等关键词的路由给 Codex；复杂任务自动 \@Orchestrator。

### 4.2 动画与过渡

#### 4.2.1 消息发送动画：缩放+淡入，模拟飞书/微信体验

消息动画的设计目标是让聊天体验流畅自然，不突兀、不拖沓。

**用户消息发送动画**：用户点击发送后，消息气泡在输入框位置以 scale 0.8 +
opacity 0 的初始状态出现，300ms 内过渡到 scale 1.0 + opacity 1（easing:
cubic-bezier(0.34, 1.56, 0.64,
1)，即轻微的弹簧过冲效果），同时消息气泡从输入框位置向上滑动到消息列表底部（translateY
40px → 0）。这一动画模拟了消息"飞入"聊天的感觉，与飞书、微信等成熟 IM
产品的体验一致 。

**Agent 消息接收动画**：Agent 消息从左侧以 opacity 0 + translateX(-20px)
的初始状态进入，400ms 内过渡到 opacity 1 + translateX(0)（easing:
cubic-bezier(0.4, 0, 0.2,
1)）。如果消息包含代码块或预览卡片，卡片内部的内容以 stagger
方式依次进入------文本先出现（0ms），代码块标题栏随后（100ms
delay），代码内容最后（200ms delay），形成层次分明的视觉节奏。

**流式消息更新动画**：SSE 流式输出时，新到达的 token
不使用动画（确保渲染频率），但代码块从文本状态切换到语法高亮状态时有一个微妙的淡入过渡（opacity
0.3 → 1.0，200ms）。流式完成后，整个消息气泡有一个微弱的闪烁（背景色从
#ffffff 短暂变为 #faf9ff 再恢复，400ms），标示消息已完成。

#### 4.2.2 Agent 思考状态：呼吸动画+"正在思考..."文字

Agent
思考状态需要传达"正在处理但尚未输出"的信息，同时保持视觉上的优雅不干扰。

**头像呼吸动画**：Agent 头像外圈有一个 2px 宽的主色调圆环，以 2s
为周期进行呼吸效果------scale 1.0 → 1.08 → 1.0，opacity 0.6 → 1.0 →
0.6，easing: ease-in-out。这种呼吸感模拟了"活跃思考"的生命感。

**渐变文字动画**："正在思考..." 文字后方有三个圆点，以 stagger
方式依次进行 scale 0 → 1 → 0 的弹跳动画（每个圆点间隔
300ms，单个动画时长 600ms）。当思考时间超过 5 秒时，文字动态更新为
"正在分析需求..."、"正在规划任务..." 等更具体的描述，让用户了解 Agent
当前的处理阶段。

**骨架屏过渡**：思考超过 2 秒后，在 Agent
消息将要出现的位置展示骨架屏占位（灰色矩形条，shimmer
动画）。骨架屏的高度根据即将返回的消息类型预估------纯文本消息显示 2-3
行骨架条，代码块消息显示一个代码块轮廓，预览卡片显示一个矩形占位。这样当真实消息到达时，用户已经形成了对内容类型的预期，减少了视觉跳跃。

#### 4.2.3 页面切换：淡入淡出，保持上下文连续性

AgentHub
作为单页应用（SPA），页面切换动画强调上下文的连续性，让用户始终感知自己在同一个工作空间中。

**会话切换**：点击左侧会话列表切换会话时，中间聊天区域以 opacity 1 →
0（100ms）→ opacity 0 → 1（200ms）的淡入淡出过渡，同时消息列表内容从下方
10px 位置滑入。整个切换时长控制在 300ms 以内，避免用户感知到明显的等待。

**右侧面板切换**：右侧信息面板在 "参与者"、"产物"、"部署历史"
三个标签间切换时，当前内容向左滑出（translateX 0 → -20px，opacity 1 →
0，150ms），新内容从右侧滑入（translateX 20px → 0，opacity 0 →
1，200ms）。这种滑动方向暗示了标签之间的空间关系。

**模态框动画**：所有模态框（部署配置、全屏预览、Agent
详情）的打开动画采用 scale 0.95 → 1.0 + opacity 0 → 1（200ms
cubic-bezier(0.16, 1, 0.3, 1)），关闭动画反向（150ms cubic-bezier(0.4,
0, 0.2, 1)）。背景遮罩的淡入淡出时长与模态框同步。这种弹簧 easing
让弹窗有"弹出"的生动感。

**路由级页面切换**：从主聊天界面切换到 Agent
市场或设置页面时，使用共享布局元素（顶部导航栏、左侧边栏保持不动），只有主内容区域以淡入淡出过渡。这保持了用户对导航结构的稳定认知。

### 4.3 快捷键设计

#### 4.3.1 Cmd/Ctrl+K：快速跳转对话

Cmd/Ctrl+K 是 AgentHub 的"万能跳转"快捷键，唤起命令面板（Command
Palette），这是面向高级用户效率操作的核心入口。

**命令面板设计**：面板从顶部居中位置下拉出现（宽度 560px，最大高度
400px，圆角 12px，阴影 0 16px 48px
rgba(0,0,0,0.12)）。顶部是搜索输入框（高度 48px，无边框，placeholder
"搜索会话、Agent、命令..."），下方是结果列表。

**搜索结果分类**：结果按类别分组------"最近会话"（按最近活跃时间排列，最多
5 条）、"Agent"（匹配的 Agent 列表）、"命令"（如
"新建对话"、"部署项目"、"打开设置"）。每个结果项展示对应图标、名称和快捷键提示（如有）。

**键盘导航**：上下方向键选择结果（选中项以 #f3f4f6 背景高亮），Enter
确认执行，Esc 关闭面板。选择会话时直接跳转，选择 Agent
时在新对话中打开与该 Agent 的会话，选择命令时执行对应操作。

#### 4.3.2 Cmd/Ctrl+N：新建对话

Cmd/Ctrl+N 唤起新建对话流程，这是用户开始新任务的最快捷方式。

按下快捷键后，界面中央弹出 "新建对话" 模态框（宽度 480px，圆角
16px）。模态框顶部是标题 "新建对话"，主体是 Agent 选择网格（展示所有可用
Agent 的头像和名称，单选），底部是 "创建" 和 "取消"
按钮。用户可以直接在网格中选择一个 Agent 开始对话，或选择 "多 Agent
群聊" 选项进入群聊配置。

高级用法：支持在快捷键后连续输入。例如 Cmd+N 后立即键入
"Claude"，新建对话模态框的搜索框自动填充 "Claude" 并过滤结果，用户只需按
Enter 即可快速创建与 Claude Code 的对话。

#### 4.3.3 \@键：唤起 Agent 选择器

在聊天输入框中键入 "@" 字符是 AgentHub 最核心的交互机制之一。

**触发条件**：@字符在输入框的任意位置键入都会唤起 Agent 选择器浮层。如果
\@前面有空格或位于输入框开头，选择器正常弹出；如果 \@紧跟在字母后（如
"hello@"），则不触发（避免干扰邮箱地址输入）。

**选择器交互**：浮层最大高度 280px，展示所有可用
Agent。键盘上下方向键选择，Enter 确认，Esc 关闭。选中后，Agent
名称以彩色药丸标签插入输入框中，标签颜色为该 Agent
的标识色。药丸标签可以通过 Backspace
删除（整个标签一起删除，不是逐字符）。

\*\*快捷 @\*\*：输入 \@后，可以直接键入 Agent
名称的前几个字母进行过滤，然后按 Tab 自动补全。例如键入 "@clau" 后按
Tab，自动补全为 "@Claude Code" 的药丸标签。

#### 4.3.4 Esc：关闭预览/退出全屏

Esc 键作为"退出/关闭"的通用快捷键，在 AgentHub
的多个场景中承担统一的退出功能：

**关闭全屏预览**：当网页预览卡片处于全屏模态时，Esc
关闭全屏，恢复到聊天流中的内联卡片状态。

**关闭模态框**：所有模态框（部署配置、Agent 详情、命令面板、设置）都支持
Esc 关闭，关闭动画反向播放。

**取消选择**：在聊天输入框中，如果有文本被选中，第一次 Esc
取消选择；第二次 Esc 清空输入框（如果有内容）或关闭相关浮层。

**退出编辑模式**：当产物处于编辑模式（代码编辑器全屏）时，Esc
退出编辑模式，返回预览状态。如果存在未保存的修改，弹出确认对话框
"有未保存的修改，确定要退出吗？"

### 5.2 字体与排版

#### 5.2.1 字体栈：Inter（UI）+ JetBrains Mono（代码）

AgentHub 采用双字体栈策略------UI
元素使用无衬线字体确保屏幕阅读的清晰度，代码元素使用等宽字体保持字符对齐的精确性
[^34] 。

**UI
字体栈**：`'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Hiragino Sans GB', 'Microsoft YaHei', sans-serif`。Inter
是专为屏幕 UI
设计的高品质无衬线字体，数字和字母的宽度经过优化，在小字号下仍有出色的可读性。中文字体回退链使用系统字体（苹方
→ 冬青黑 → 微软雅黑），确保中文内容的渲染速度和一致性。

**代码字体栈**：`'JetBrains Mono', 'Fira Code', 'Consolas', 'Monaco', 'Courier New', monospace`。JetBrains
Mono
是专为编程设计的等宽字体，字符高度一致、字母间距经过优化、支持编程连字（ligatures），为代码阅读和编辑提供最佳体验
[^35]。

**字体加载策略**：Inter 和 JetBrains Mono 均通过 Google Fonts CDN
加载，使用 `font-display: swap`
确保文字立即渲染（先以系统字体展示，自定义字体加载完成后无缝切换）。为了控制加载体积，Inter
只加载 Latin 子集（用于英文 UI），中文字体完全依赖系统字体。

#### 5.2.2 字号层级：标题 18px、正文 14px、辅助 12px、代码 13px

AgentHub 的字号系统采用 4 级层级，每级有明确的用途和样式定义：

  -----------------------------------------------------------------------------------------
  层级       字号       字重       行高       字间距     使用场景
  ---------- ---------- ---------- ---------- ---------- ----------------------------------
  大标题     18px       600        1.4        -0.01em    页面标题、模态框标题、会话名称

  正文       14px       400        1.6        0          消息内容、表单标签、描述文字

  辅助       12px       400        1.5        0          时间戳、提示文字、标签、统计数字

  代码       13px       400        1.5        0          代码块、System Prompt、日志输出

  极小       11px       500        1.4        0.01em     徽章文字、状态标签、胶囊标签
  -----------------------------------------------------------------------------------------

大标题使用 semibold（600）字重确保层级分明，正文使用
regular（400）确保长时间阅读的舒适性，辅助文字缩小 2px
并适当收紧行高以节省空间。代码字号设定为 13px（比正文小
1px），这是经过实测的最佳代码阅读尺寸------比 12px 更易辨识字符细节，比
14px 在同等宽度内显示更多代码 。

**Markdown 排版**：AI 消息中的 Markdown 内容遵循以下排版规则------H1
18px semibold（底部 8px 分割线），H2 16px semibold，H3 14px
semibold，段落 14px regular（段间距 8px），无序列表 14px（项目符号为 6px
圆点，缩进 20px），有序列表 14px（数字编号缩进 20px），引用块 14px
italic（左侧 3px 主色调竖线，背景 `#f9fafb`），表格 13px（表头背景
`#f3f4f6`，行交替背景 `#fafafa`，单元格内边距 8px 12px）。

### 5.3 间距与圆角

#### 5.3.1 卡片圆角：12px 大圆角（容器）+ 8px 小圆角（消息气泡）

AgentHub
的圆角系统采用两级设计，大圆角用于顶层容器，小圆角用于内部元素，形成层次分明的视觉节奏。

**大圆角
12px**：用于顶层容器级元素------模态框、命令面板、下拉浮层、产物预览卡片、部署配置面板。12px
的圆角传达现代、友好的视觉感受，与当前主流 SaaS 产品的设计语言一致。

**中圆角
8px**：用于次级容器------消息气泡、按钮、输入框、文件卡片、Agent
卡片。8px 的圆角在保持现代感的同时，为高频交互元素提供更紧凑的视觉边界。

**小圆角
4px**：用于内联元素------代码内联标签、徽章、提示框、工具提示（tooltip）。4px
的微圆角柔化了小型元素的尖锐感。

**特殊圆角 ---
消息气泡不对称圆角**：消息气泡使用方向性圆角模拟"发言指向"------用户消息右下圆角
4px（指向右侧发送者），Agent 消息左上圆角
4px（指向左侧发言者），其余三个角 12px。这种不对称设计是 IM
产品的经典视觉语言，让用户在快速滚动时也能通过圆角方向区分消息来源。

#### 5.3.2 间距系统：4px 基数的 8px/12px/16px/24px/32px 层级

AgentHub 的间距系统基于 4px 基数（baseline grid），所有间距值都是 4
的倍数，确保界面元素的对齐一致性。

  ------------------------------------------------------------------------------
  间距令牌             数值                 使用场景
  -------------------- -------------------- ------------------------------------
  xs                   4px                  图标与文字间距、紧凑内联间距

  sm                   8px                  按钮内边距（上下）、小元素间距

  md                   12px                 卡片内边距、表单字段间距

  lg                   16px                 消息气泡内边距、卡片间距、段落间距

  3xl                  48px                 独立区块间距、页面标题与内容的间隔

## 6. 创新亮点设计

### 6.1 协作规范自动生成

#### 6.1.1 对话中识别模式，自动生成 Rules 文件（.cursorrules 格式）

协作规范自动生成是 AgentHub
最具技术深度和创新价值的亮点功能，直接对应赛题评审中权重最高的 "AI
协作能力" 维度（30%）[^36]。业界已有 AGENTS.md（13.5K
Stars）等开源项目验证了 AI 协作规范的标准化趋势
，但现有工具均需要开发者手动编写和维护这些规范。AgentHub
的突破在于------通过分析用户与 Agent
的对话过程，自动提取和生成协作规范，让规范沉淀成为协作的自然副产品。

**设计目标**：当用户在 AgentHub 中与 Agent
进行了多轮协作后，系统能够识别出稳定的协作模式------如代码风格偏好、项目结构约定、审查标准、命名规范等------并自动将这些模式转化为结构化的
Rules 文件。这些规则随后会作为 System Prompt 的附加上下文注入到对应
Agent 的后续调用中，使得 Agent 的行为越来越符合用户的实际偏好。

**交互流程**：用户在与 \@Claude Code 完成了 5-6
轮代码生成和修改后，聊天界面顶部出现一个微妙的提示条（黄色背景，高度
36px）："检测到稳定的代码风格模式 --- 是否生成为协作规范？" 点击 "生成"
后，系统展示一个 "规范生成" 模态框，内含三个标签页：

- **代码风格规则**：系统自动提取的规范------如 "使用 TypeScript
  严格模式"、"React 函数组件优先于 Class 组件"、"Tailwind CSS
  类名按布局→间距→颜色→动画排序"、"组件文件使用 PascalCase
  命名"。每条规则旁边有 "编辑" 和 "删除"
  按钮，用户可以微调自动提取的结果。
- **项目结构规则**：从对话中推断的项目组织约定------如 "组件存放在
  src/components 目录"、"页面级组件存放在 src/pages"、"工具函数存放在
  src/utils"。
- **审查偏好规则**：从用户对代码审查意见的接受/拒绝模式中提炼------如
  "优先关注安全性问题"、"忽略样式细节建议"、"要求所有函数必须有 JSDoc
  注释"。

规范确认后，以 `.cursorrules` 文件格式保存到项目根目录
，并在右侧信息面板的 "规范"
标签中展示。每次创建新的对话时，系统提示是否继承已有规范------"检测到当前项目已有
12 条协作规范，是否应用？"

**核心技术逻辑**：规范生成依赖三层 LLM
调用------第一层实时分析每条用户反馈（接受/拒绝/修改代码），提取显性和隐性的偏好信号；第二层在积累了
5-10 条信号后，归纳出稳定的模式规则；第三层将规则格式化为标准的
`.cursorrules` 或 `AGENTS.md`
格式，并进行冲突检测和去重。整个过程对用户透明，不干扰正常的协作流程。

#### 6.1.2 常用操作序列识别为 Skill，一键保存复用

Rules 描述的是"做什么"的静态规范，而 Skill
描述的是"怎么做"的动态流程。AgentHub
能够识别用户在协作中反复使用的操作序列，将其封装为可复用的 Skill。

**识别场景**：用户经常执行以下类型的重复序列------"创建新页面"（创建组件文件
→ 添加路由 → 编写基础布局 → 添加导航链接）、"添加 CRUD
API"（创建路由文件 → 定义请求/响应类型 → 编写数据库查询 → 添加参数校验 →
编写测试用例）、"组件审查流程"（发送代码给 \@CodeReviewer → 等待审查报告
→ 转发修复建议给 \@Claude Code → 确认修改）。

**Skill
卡片设计**：当系统检测到用户第三次执行相似的操作序列时，聊天界面底部浮现一个
Skill 保存提示："检测到您已多次使用'创建新页面'流程 --- 保存为 Skill
以便一键调用？" 点击后弹出 Skill 编辑器，以流程图形式展示操作序列（使用
React Flow 库实现 [^37]），每个步骤是一个节点（展示 Agent 头像 +
操作描述 + 默认 Prompt），步骤之间有连线（展示执行顺序和条件分支）。

用户可以编辑流程------添加步骤、删除步骤、修改 Prompt
模板、添加条件判断。保存后的 Skill 出现在 "我的 Skill"
面板中，使用时点击即可一键触发整个流程，无需逐条 \@Agent 和输入指令。

**Skill 的市场化**：用户可以将自己创建的 Skill 发布到 Agent
市场，其他用户一键安装后可以在自己的项目中使用。系统预置 5 个高频 Skill
模板：全栈页面开发、组件库添加、API 接口开发、Bug
修复协作流、代码重构流程。

#### 6.1.3 项目 Spec 文档自动生成与维护

在软件工程实践中，项目规格说明（Spec）是团队协作的基础文档。AgentHub
通过与 Agent 的协作过程，自动维护和更新项目 Spec 文档。

**自动提取**：当用户与 Orchestrator 讨论项目需求时（如
"我要做一个博客系统，支持文章 CRUD 和标签分类"），Orchestrator
自动将这些需求转化为结构化的 Spec
文档------包含功能需求列表、数据模型定义、API
接口规格、页面路由规划。Spec 以 Markdown 格式保存在项目的 `docs/SPEC.md`
路径下。

**变更追踪**：当用户在后续对话中修改需求（如 "再加一个评论功能" 或
"文章不要标签了，改成分类"），Orchestrator 检测 Spec 的变更点，以 Diff
形式展示变更内容（新增行绿色、删除行红色），用户确认后 Spec
自动更新。变更历史保留在 `docs/SPEC_HISTORY.md` 中。

**Spec 驱动的协作**：一旦 Spec 文档建立，后续的 Agent 协作都以 Spec
为基准。当用户说 "按照 Spec 实现文章列表页" 时，Claude Code 自动读取
Spec 中的相关章节，理解数据模型、API 规格和页面要求后再生成代码。这种
Spec 驱动的模式显著减少了 Agent "偏离需求" 的问题 。

**人机协作节点**：Spec
的重大变更（如修改数据模型、删除功能模块）需要用户显式确认------Orchestrator
展示变更影响的范围（"此变更将影响 3 个已生成的组件和 2 个 API
接口"），用户确认后才执行修改。

**Agent 导入**：用户通过链接安装或上传 `.agenthub` 文件导入

**排名与发现**：市场首页提供多种排序方式------最受欢迎（下载量）、最高评分、最近更新、趋势上升（近
7 天下载增长率）。推荐算法基于用户的使用历史和技术栈偏好，在 "为你推荐"
板块展示可能感兴趣的 Agent。

### 6.3 Coze 生态深度集成

#### 6.3.1 一键导入 Coze Bot 作为 Agent

Coze（扣子）是字节跳动推出的新一代 AI Agent
平台，拥有数百万开发者和丰富的 Bot 生态 [^38] [^39]。AgentHub 与 Coze
的深度集成是展示字节生态理解力的关键设计，也是打动评审导师（来自扣子部门）的隐性加分项
。

**导入流程**：用户在 Agent 市场中切换到 "Coze Bot" 标签页，系统通过 Coze
Open API 拉取用户已创建的 Bot 列表。每个 Bot
展示头像、名称、描述和最近使用时间。用户勾选想要导入的 Bot，点击
"一键导入" 按钮。

导入过程包含三个自动步骤：第一步，AgentHub 调用 Coze API 获取 Bot
的详细配置（System Prompt、工具集、知识库引用）；第二步，将 Coze Bot
的配置映射为 AgentHub 的 Agent 配置格式------Coze 的 "Persona & Prompt"
映射为 AgentHub 的 System Prompt，Coze 的 "Plugins" 映射为 AgentHub
的工具集，Coze 的 "Knowledge" 映射为 AgentHub
的上下文文件；第三步，生成新的 Agent
并添加到用户联系人列表，头像和名称保持与 Coze Bot 一致。

导入完成后，用户可以在 AgentHub 的群聊中 \@这个从 Coze 导入的
Agent，与其他 Agent 协同工作。例如：用户导入了一个 Coze 上创建的
"产品经理助手" Bot，在开发博客系统的群聊中可以 \@产品经理助手
帮忙梳理用户故事，然后将需求转发给 \@Claude Code 实现。

**技术映射**：Coze 与 AgentHub
的能力映射并非完全一对一，系统会在导入时展示
"能力兼容性报告"------绿色标记完全兼容的功能、黄色标记部分兼容的功能（如
Coze 特有的 "长期记忆" 能力在 AgentHub 中通过 Rules
文件近似模拟）、红色标记不兼容的功能（如 Coze 的 "语音交互" 能力在 Web
端暂不支持）。

#### 6.3.2 发布 Agent 到 Coze 平台

导入的双向通道------AgentHub 中创建的 Agent 也可以发布到 Coze 平台，让
Coze 生态的用户使用。

**发布流程**：用户在 Agent 详情页面点击 "发布到 Coze"
按钮，系统展示发布配置面板。AgentHub 自动将 Agent 的配置反向映射为 Coze
Bot 的格式------System Prompt 映射为 "Persona & Prompt"，工具集映射为
"Plugins"，Rules 文件映射为 "Knowledge"
引用。用户可以选择发布到个人空间或团队空间，设置 Bot
的可见性（公开/私密）。

发布成功后，系统在 Agent 详情页面展示 "已在 Coze 发布"
的标识和跳转链接。用户在 Coze 平台上可以进一步配置 Bot 的
Trigger（触发器）、Memory（长期记忆）和 Workflow（工作流），这些 Coze
特有的能力作为 AgentHub 的补充。

**生态闭环**：导入 + 发布的双向通道形成了 AgentHub 与 Coze
之间的生态闭环。开发者在 AgentHub 中利用多 Agent 协作能力开发和完善
Agent，然后将成品发布到 Coze 平台服务更广泛的用户。这一设计展示了
AgentHub 作为 "Coze 生态增强层" 的定位，而非独立的竞品。

#### 6.3.3 利用扣子工作流扩展 Agent 能力

Coze 最强大的功能之一是可视化工作流编排（Workflow）[^40]。AgentHub
允许用户将 Coze Workflow 作为外部工具集成到自己的 Agent 中。

**Workflow 工具集成**：用户在 Agent 的工具配置中，选择 "添加 Coze
Workflow" 工具。系统通过 Coze API 拉取用户已有的 Workflow
列表，用户选择一个 Workflow（如 "内容审核工作流" 或
"数据增强工作流"）并配置调用参数映射。配置完成后，该 Agent
在对话中可以调用这个 Coze Workflow 作为其工具集的一部分。

**使用场景**：用户在开发一个内容管理平台时，@Claude Code
生成的文章需要经过内容审核。Claude Code 可以调用集成的 Coze
"内容审核工作流"
工具，将生成的文章自动提交审核，审核结果（通过/拒绝/需修改）作为工具调用结果返回到聊天流中，Claude
Code 根据审核结果自动修改内容。

**工作流调用展示**：当 Agent 调用 Coze Workflow
时，聊天流中展示一个特殊的 "Workflow 调用" 卡片------展示 Workflow
名称、输入参数摘要、执行状态（旋转进度条）和输出结果。这种透明展示让用户清楚了解
Agent 正在使用的外部能力和执行进展。

Coze 生态深度集成的三个层面（导入 Bot、发布 Agent、集成
Workflow）共同构成了 AgentHub 与字节跳动 AI
生态的无缝连接。这一设计不仅提升了产品的实用价值，更在评审层面展示了团队对字节跳动
AI 战略的深刻理解和产品落地能力。
